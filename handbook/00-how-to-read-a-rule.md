# 怎么读一张规则卡片

这本手册收着阶段 0 和阶段 1 的 30 张规则卡片，按类别分章，索引在 [README.md](README.md)。卡片的原文写在每一课文件夹的 `rules.md` 里，手册里的是工具照抄的副本。

## 两个问题，分开问

每张卡片都分开回答两件事：

- **规则类型**：这条规则是谁定的。一共七种，见下表。
- **约束力**：它在你的处境里有多强制。分三级：必须、推荐、参考。后面的括号写它在哪个范围里成立：本课程、本机、所在团队或所有项目。例如「必须（适用范围：本课程）；推荐（适用范围：所有项目）」。

规则类型分好就不再变。处境变了，变的只是约束力。

## 七种规则类型

| 规则类型 | 一句话 |
|---|---|
| 标准 | 标准组织正式发布、带编号的文件，比如 RFC 2119、PEP 8 |
| 行业要求 | 第三方能拿来追究你的：法律、法规、合同、审计、平台的强制政策 |
| 惯例·事实标准 | 公开、有版本号、很多互不相干的项目和工具都在用的社区规范，比如约定式提交 1.0.0 |
| 惯例·平台与工具 | 某个工具或平台本来就这样工作、这样期待，比如 GitHub 把根目录的 `README.md` 显示在项目首页 |
| 规范·组织 | 一家组织以自己的名义写的做法指南，比如 Google 的风格指南 |
| 规范·团队约定 | 这个团队、这个仓库自己定的；只因为本课程这样选而存在的，写成「规范·本课程约定」 |
| 个人偏好 | 不是规则，可以自己决定，所以不会出现在卡片上 |

雇主对从业者的普遍期望另有一个名字：「岗位期望」，它不是法律义务。日常中文里「规范」也常被当成所有这些的总称；卡片上的「规范」只指表里那两类。

## 卡片上的每一项

| 项 | 写的是什么 |
|---|---|
| 约束力 | 多强制，在哪个范围里 |
| 规则类型 | 七种之一 |
| 规则 | 可以照着做的一句话 |
| 谁说的 | 出处：名称、版本或日期、网址 |
| 核对日期、复核周期 | 哪天有人打开原文核对过；过多久要再核对一次（法律和平台政策 6 个月，工具和平台的惯例 12 个月，稳定的社区规范 24 个月） |
| 谁来管、不遵守的后果 | 谁真的能发现或追究；不照做会怎样 |
| 为什么 | 两三句，讲后果 |
| 正例、反例 | 照着做的样子；不该做的样子 |
| 怎么检查 | 一条自检命令、一道复习题，或者“人工检查” |
| 例外 | 什么时候可以不照做 |
| 旧教程提醒 | 老资料里的过时说法和现在的做法，写明从哪个版本或哪一年起 |
| 学于 | 在哪一课学到 |

## 想看全貌

怎么判断一条规则属于哪一类（七步判断法），三级约束力和别的用词怎么对应，30 条规则的总表，都在[规范地图](../STANDARDS.md)第 2、3 节。

每条规则用你自己的话写在 `notes/my-rules.md` 里。
