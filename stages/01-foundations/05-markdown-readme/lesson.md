## 第 1 站：Markdown 语法（约 35 分钟）

### 概念

**Markdown**（Markdown）是一种写纯文本的约定：用几个普通符号标出文字的结构。一行开头写 `# `，它就是标题；一行开头写 `- `，它就是清单里的一项。文件仍是纯文本；支持 Markdown 的程序会把这些符号“翻译”成排好版的样子，叫**预览**（preview）：只是看，不改文件。

回到「先想一想」：你可能会在标题前后加【】，在重要的词两边加星号。Markdown 把这类土办法定成了大家都认的写法，所以基本写法在 VS Code、GitHub（存放代码的网站，第 1.11 课注册）等工具里显示得一样。

打个比方：Markdown 像改稿时用的校对符号，写在文字里，懂的人一看就知道哪里要变成什么样。**这个比方在哪里不成立**：校对符号是给人看的，写歪一点人也认得；Markdown 的符号是给程序看的，少一个空格它就不认了，而且不报错，只把它当普通文字显示。

这一站用到的写法：

| 想要的效果 | 怎么写 | 要点 |
|---|---|---|
| **标题**（heading） | `# 一级标题`、`## 二级标题` | `#` 的个数是级别；`#` 后面要有一个空格 |
| 列表 | `- 第一项` | 每项一行；`-` 后面要有一个空格 |
| 加粗 | `**要紧的话**` | 两边各两个星号 |
| **行内代码**（inline code） | `` `cd` `` | 两边各一个反引号 `` ` ``（英文输入法下，数字 1 左边那个键） |
| **代码块**（fenced code block） | 上下各一行 ```` ``` ```` | 中间几行原样显示；开头那行可以写上是哪种代码，比如 ```` ```zsh ````（zsh 是你终端里那个 shell 的名字） |
| 链接 | `[显示的文字](网址)` | 方括号紧挨圆括号，中间没有空格 |

所有符号都是**半角**的（英文输入法下打出来的那种）。中文输入法打出的 `＃`、`【】`、`（）`，Markdown 都不认。

**以谁为准**：这些写法出自 CommonMark 0.31.2（2024-01-28，目前最新），一份公开、有版本号、很多工具照着做的社区规范。规则类型：**惯例·事实标准**；约束力：必须（适用范围：本课程）；推荐（适用范围：所有项目）。https://spec.commonmark.org/ ，2026-11-20 核对。

本课程另有一条约定：**一个文件只有一个一级标题**，小节用二级标题。约束力：必须（适用范围：本课程）；规则类型：**规范·本课程约定**，是这门课自己定的，本课的两个检查都会看。

> **旧教程提醒**：老教程里 `#标题`（`#` 后面不空格）也算标题；现在 CommonMark 要求这个空格，GitHub 也照它显示 Markdown 文件（自 2017-03-14 起，见 GitHub 官方博客《A formal spec for GitHub Flavored Markdown》）。

> **中文输入法的坑**〔建课时无法验证〕：中文输入法下，反引号那个键可能打出 `·` 或 `｀`，括号、`#` 和空格也可能变成全角的。打符号前先切到英文输入法（ABC）。在终端里敲命令也一样：命令里混进全角空格，zsh 会说 `command not found` 或 `no such file or directory`，后面跟着连在一起的那一整串。读懂这句：找不到这个命令，或者没有这个文件或文件夹；zsh 把全角空格当成了普通的字，整串被当成了一个名字。

#### 4. 看预览

〔对照文档，界面可能不同〕光标在 `weekend.md` 里时，按 ⇧⌘V（⇧ 是 Shift 键）打开预览：`周末计划` 是大号标题，清单前面有圆点，`cd` 显示成代码，`MDN` 可以点。想边写边看，先按 ⌘K 再按 V，预览出现在右边。

预览只是“看”：文件里还是那些符号，排版只发生在预览的那一刻。

#### 5. 故意出个错

〔对照文档，界面可能不同〕回到 `weekend.md`，把第一行 `# 周末计划` 里 `#` 后面的空格删掉，变成 `#周末计划`，保存，再看预览：大号标题不见了，那一行变成了普通大小的文字 `#周末计划`。

用“报错三问”读它：

1. **谁在报错？** 没有程序报错。Markdown 从不报错，认不出的写法就当普通文字显示，所以只能靠看预览发现问题。
2. **关键词是什么？** 预览里原样露出来的那个 `#`：符号原样出现，说明写法没被认出来。
3. **我刚才敲了什么？** 删掉了 `#` 后面的空格。CommonMark 规定这里至少要有一个空格。

把空格加回去，保存，确认标题又变大了。

## 第 2 站：README 是项目的门面（约 30 分钟）

### 概念

**README**（README，意思是“先读我”）是放在项目**根目录**（root directory：项目最外层的那个文件夹，比如 my-site 本身）里的说明书，回答陌生人第一次打开项目时最先想问的问题。GitHub 会把它排好版，直接显示在项目的首页上，所以它是别人对你项目的第一印象。

打个比方：README 像店门口的招牌和告示，写着这是什么店、几点营业、怎么进门。**这个比方在哪里不成立**：没人强制你写 README，你的代码照样能运行；但没有它，别人不敢进门，几个月后的你自己也会忘了当初怎么用。

这门课要求 README 依次回答五个问题（本课程约定，见文末 DOC-02）：

1. **这是什么？** 一两句话说清楚。
2. **怎么用，怎么看到效果？** 别人照着做就能看到结果的步骤，命令放在代码块里。
3. **文件夹里有什么？** 每个主要文件是干什么的。
4. **现在的状态和打算？** 做到哪了，下一步做什么。
5. **作者是谁，用什么许可证？** 许可证说的是别人能不能用你的东西。这一课只写作者（可以写笔名），许可证第 1.13 课再加。

### 跟我做

#### 1. 打开一个没有说明的项目

练习场景里有一个小程序 hello-fx。假装你第一次见到它。先猜：这个文件夹是干什么的？

```zsh

```

你应该看到：

```text
convert.py
rates.txt
```

只看文件名，你能说出它是干什么的、怎么运行吗？很多项目的说明书叫 README.md，找一找：

```zsh
cat README.md
```

你应该看到：

```text
cat: README.md: No such file or directory
```

> 读懂这句：cat 说，README.md 这个文件或文件夹不存在。

用“报错三问”读它：

1. **谁在报错？** 行首写着 `cat`，是第 1.1 课学的那个把文件内容打印出来的命令。
2. **关键词是什么？** `No such file or directory`：没有这个文件。
3. **我刚才敲了什么？** 我让它打印 README.md，可这个项目根本没写说明书。

这就是没有 README 的感觉：你只能去猜，或者把每个文件都打开读一遍。这正是行规 DOC-01 要防的事（摘要在文末）。

#### 2. 先确认怎么运行

README 里写的命令必须真的能用。写之前先自己运行一遍。先猜它会打印什么：

```zsh

```

你应该看到：

```text

```

#### 3. 给它写一份 README

新建这个文件，再用 VS Code 打开 hello-fx 这个文件夹（会另开一个窗口）。这两条命令都不输出文字：


〔对照文档，界面可能不同〕在左边的 Explorer 里点 `README.md`，写进下面的内容（可以复制），⌘S 保存，⇧⌘V 看预览：

````markdown
# hello-fx

按固定汇率换算一笔钱的小程序，打印一行结果。

## 怎么运行

```zsh

```

## 里面有什么

- `rates.txt`：示例汇率（程序现在还没用到它）
````
