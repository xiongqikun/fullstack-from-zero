# 阶段 4：数据与 SQL

> **规划用时** 50～70 小时 ｜ **前置** 阶段 3 ｜ **核实日期** 2026-11-19 ｜ 回到[路线图](../../ROADMAP.md)

下面是计划，建这个阶段时会按你的真实进度和当时的工具重新定。

## 目标

学会把数据存进数据库（专门存数据、能快速查找的程序），并用查询语言 SQL（向数据库提问用的语言）向它提问。

学会设计表：分成哪几张，每张有哪些列，表和表怎么对上。弄懂两件保命的事：事务（几步操作要么全成、要么全不成）和备份。

## 作品

一个存着历史汇率的数据库，加一组能回答问题的查询，比如“过去三十天哪天最高”。你在终端里敲一句查询，屏幕上出现一张小表，列出日期和汇率。它是产品的账本。

历史汇率从哪里来（一份公开的数据文件，或者你自己选的数据来源），建这个阶段时和你一起定。课程的自动检查不依赖联网，用的是事先准备好的一份数据。

## 这个阶段会学到的规范（计划）

表里只标规则类型，而且是计划；约束力、谁说的、核对日期在建这个阶段时定，写在每条规范的卡片上。

| 规范 | 规则类型 |
|---|---|
| 查询里外来的值一律当参数传入，不拼进查询语句 | 惯例·平台与工具（Python 官方文档里 `sqlite3` 的说明）；同一条也写在公开的应用安全检查表里（惯例·事实标准） |
| 每张表有主键（每一行独一无二的编号）；表和表怎么对上、每一列允许放什么，都明确写进表的定义里（行话叫外键和约束） | 规范·本课程约定 |
| 表结构的每次改动写成一份可以重复执行的脚本（行话叫迁移），进仓库 | 惯例·平台与工具（迁移工具的官方文档） |
| 几步相关的修改放进同一个事务 | 惯例·平台与工具（SQLite 和 PostgreSQL 的官方文档） |
| 金额用精确数值类型 | 惯例·平台与工具（PostgreSQL 官方文档建议金额用 numeric） |
| 时间带时区并统一存 UTC（全世界共用的一把基准时钟） | 规范·本课程约定 |
| 备份做过恢复演练才算数 | 规范·本课程约定 |
| 表和列的命名、查询的书写格式全项目一致 | 规范·团队约定 |

## 过关方式

数据库能从空白一步步重建出来，查询结果和标准答案一致；阶段验收里有一道“查询变慢了，找出原因”，做这一道时不用 AI。

## 技术清单（现在看不懂没关系）

- 起步用 SQLite（建课时 macOS 自带的命令行是 3.54.0），再换 PostgreSQL。建课当天（2026-11-19）PostgreSQL 19 刚刚正式发布，18 仍受支持（18 系最新是 18.7）。学到这里时先看 19 有没有出过几个修正版，再定用哪个；在那之前课程按 18 写。
- SQL：`SELECT`、`WHERE`、`ORDER BY`、聚合、`JOIN`、`NULL`、`INSERT` / `UPDATE` / `DELETE`、建表与约束。
- 设计：主键、外键、范式；`NUMERIC` 与带时区的时间类型。
- 事务与 ACID；索引与 `EXPLAIN QUERY PLAN`。
- Python 的 `sqlite3` 模块与参数化查询；SQL 注入演示只在自己的练习库上做。
- 迁移（migration）：用什么工具，建课时定。
- 把 Docker 当电器用：用一份现成的 `compose.yaml` 起一个 `postgres:18`；psycopg 3。
- 备份与恢复演练；数据清单（data inventory）。
- 规则类型的出处：Python 文档 `sqlite3`（placeholders）；OWASP ASVS 5.0.0；SQLite 与 PostgreSQL 文档（transactions、numeric）。
