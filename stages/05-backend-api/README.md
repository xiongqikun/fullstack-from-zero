# 阶段 5：后端与接口设计

> **规划用时** 80～110 小时 ｜ **前置** 阶段 4 ｜ **核实日期** 2026-11-19 ｜ 回到[路线图](../../ROADMAP.md)

下面是计划，建这个阶段时会按你的真实进度和当时的工具重新定。**这里是下车点二**：三个特别推荐的落脚点里的第二个。

## 目标

做一个后端：一个一直开着、等别的程序来问的程序。学会设计接口（程序之间约定好的问答方式）：问法怎么定，成功和失败怎么表示，数据多了怎么分批给。第一次把后端放到网上。

## 作品

一个“数据窗口”：别的程序可以通过网址来查汇率，它从阶段 4 的数据库里取数作答，并且在网上运行。

你会看到的样子：在浏览器的地址栏里输入一个网址，页面上出现一串汇率数字，是机器读得懂的格式。你的表格、脚本或者以后的网页，都可以用同一个网址来取数。

阶段一开始，计划先用几十行代码搭一个“薄片”：接口、数据库、页面各一点点，让你把整条链看一遍，再一层一层做实。

## 这个阶段会学到的规范（计划）

表里只标规则类型，而且是计划；约束力、谁说的、核对日期在建这个阶段时定，写在每条规范的卡片上。表里的英文名字是这些规范的正式名称，学到时再讲；现在把它们当书名看就行。

| 规范 | 规则类型 |
|---|---|
| 请求的“要做什么”和应答的“结果如何”，按网络传输的标准规定的含义使用（RFC 9110，互联网标准组织编号 9110 的文件） | 标准 |
| 出错时返回统一格式的说明（RFC 9457） | 标准 |
| 接口有一份机器读得懂的说明书（OpenAPI，一份公开、有版本号的接口说明书格式） | 惯例·事实标准 |
| 接口地址用复数名词，不带动词 | 规范·组织（Zalando 公司公开的接口规范） |
| 返回一长串数据的接口，从第一天起就分批给 | 规范·组织（同上） |
| 已经发布的接口不做破坏性的改动 | 规范·组织（同上）；版本怎么标是规范·团队约定 |
| 所有进来的数据在入口处检查 | 惯例·事实标准（公开的应用安全检查表 OWASP ASVS 5.0.0 第 2 章） |
| 设置随环境变，程序不变 | 惯例·事实标准（《十二要素应用》第三条） |
| 提供一个“我还活着”的检查地址，供平台和监控探测 | 惯例·平台与工具（托管平台的官方文档） |
| 提交说明和合并请求改用英文 | 规范·本课程约定（到时由你决定；定下来以后，它就是你自己仓库的规范·团队约定） |

## 过关方式

数据窗口在网上运行，自动测试覆盖主要的问法和出错情况；阶段验收里有一道“一个请求失败了，找出卡在哪一层”，做这一道时不用 AI。

## 技术清单（现在看不懂没关系）

- HTTP：方法、状态码、标头、主体；`curl --json`；一次请求的旅程（URL、DNS、TCP、TLS、HTTP）；端口与 localhost。
- 框架：FastAPI（建课当天是 0.165.0，仍是 0.x，更新很快）、Pydantic 2、Uvicorn；先用普通的 `def`，`async def` 往后放。
- 数据层：SQLAlchemy 2.1 与 Alembic 1.20；FastAPI 官方教程里的 SQLModel 只认识一下。
- 设计：资源命名、分页、幂等、向后兼容、`application/problem+json`、OpenAPI 3.1（FastAPI 生成的版本；规范现行是 3.2.1，2026-09-10 发布）与 `/docs`；路由、服务、仓储三层。
- 测试：进程内的 `TestClient`，不开端口。
- 配置：pydantic-settings、`.env.example`；`/healthz`。
- 薄片：FastAPI 加标准库 `sqlite3` 加一个 Jinja 模板。
- 上线：先不写 Dockerfile，用托管平台自带的 Python 运行环境，加一个托管的 PostgreSQL。平台到时再选，免费档一直在变。
- 安全：输入校验、不泄露内部报错、SSRF、第一版 `THREAT_MODEL.md`。
- 规则类型的出处：RFC 9110、RFC 9457（IETF）；OpenAPI Initiative；Zalando RESTful API Guidelines；OWASP ASVS 5.0.0 V2；12factor.net III。
- 关卡编号（暂定）：`gate-5`。
