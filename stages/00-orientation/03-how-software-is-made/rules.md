### META-02 每条规范问三件事：谁说的、多强制、哪年的版本

- **约束力**：推荐（适用范围：本课程）
- **规则类型**：规范·本课程约定
- **规则**：遇到一条规矩，先问三件事再决定照不照做：谁说的（名称、网址），多强制（必须、推荐还是参考，在什么范围里），哪年的版本（原文是哪一版、你哪天核对的）。
- **谁说的**：本课程的建课计划里讲规则标注的那一节（docs/plans/2026-11-19-batch-1-plan.md，2026-11-19 版）和规范地图 `STANDARDS.md` 第 1、2 节；三级约束力对应 RFC 2119「Key words for use in RFCs to Indicate Requirement Levels」（1997 年 3 月，属于「最佳现行实践」BCP 14，即 IETF 正式发布的做法指导）及其补充 RFC 8174（2017 年 5 月）https://www.rfc-editor.org/info/rfc2119 、https://www.rfc-editor.org/info/rfc8174
- **核对日期**：2026-11-20；**复核周期**：12 个月，或者 STANDARDS.md 改动规则类型的分法时
- **谁来管**：没有人；本课程每一张规则卡片都按它写，导师讲任何做法时也示范这三问；**不遵守的后果**：把过时的说法、或者某个人的口味，当成必须遵守的规矩照做。
- **为什么**：同一条“规矩”，可能是法律，可能是一家公司自己的习惯，也可能只是一篇旧博客里的话。不问出处，就分不清哪些必须做、哪些可以不做。不问版本和日期，就会照着几年前的说法做，比如去装一个早已停止维护的 Python。它是规范·本课程约定：七步判断法问到第 6 步才是「是」，这条做法是本课程自己定的；它借用的「必须、推荐、参考」三级用词来自 RFC 2119，但借用不改变这条规矩本身的来源。
- **正例**：

      有人说：Python 代码一级缩进用 4 个空格。
      谁说的：PEP 8，https://peps.python.org/pep-0008/ （标准）
      多强制：推荐（适用范围：所有项目）；PEP 8 自己说，项目自己的风格指南优先
      哪年的版本：页面写着 2025-04-04 修改；2026-11-20 核对

- **反例**：网上看到“提交说明第一行不能超过 50 个字符，这是 Git 的规定”，没查出处就当成必须。Git 自己的说明书（man page）说，这是个好主意，但不是强制要求。
- **怎么检查**：复习题 0.3-three-questions；人工检查：`notes/my-rules.md` 里你写下的每一条规矩，都写了谁说的、多强制、哪天核对的。
- **例外**：明说是个人偏好的事（编辑器配色、终端字体），不是规矩，不用问这三件事。
- **旧教程提醒**：以前很多教程把“提交说明第一行不超过 50 个字符”说成 Git 的硬性规定；现在 Git 官网上的说明书 https://git-scm.com/docs/git-commit 的 DISCUSSION 一节说它“不是必须的，但是个好主意”（2026-11-20 核对：这一页最后改动于 Git 2.55.0，Git 2.54 自带的说明书里这句话一字不差）。至少从 2014 年的 Git 2.0.5 起，说明书就说它不是必须的（当时写的是少于 50 个字符，后来改成不超过 50 个）。
- **学于**：0.3
