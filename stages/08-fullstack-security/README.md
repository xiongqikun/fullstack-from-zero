# 阶段 8：全栈整合与安全

> **规划用时** 100～140 小时 ｜ **前置** 阶段 5 和阶段 7 ｜ **核实日期** 2026-11-19 ｜ 回到[路线图](../../ROADMAP.md)

下面是计划，建这个阶段时会按你的真实进度和当时的工具重新定。

## 目标

把前端、后端、数据库合成一个完整的应用，加上登录和每个人自己的设置。对照公开的安全清单，把常见的漏洞一个个堵上。学会保护用户的个人信息。

## 作品

看板有了登录和个人设置，比如各人关注的币种：你用自己的账号登录，看到的是自己挑的几种币；换一个账号登录，看不到你的设置。看板还通过了一份写明证据的安全自查。

## 这个阶段会学到的规范（计划）

表里只标规则类型，而且是计划；约束力、谁说的、核对日期在建这个阶段时定，写在每条规范的卡片上。表里的英文名字是这些规范的正式名称，学到时再讲；现在把它们当书名看就行。

| 规范 | 规则类型 |
|---|---|
| 对照 OWASP 十大风险（2025 版；OWASP 是一个公开的网络安全社区）逐项自查 | 惯例·事实标准 |
| 用 OWASP ASVS 5.0.0（应用安全验证标准，一份公开、有版本号的检查表）的一级要求当检查表 | 惯例·事实标准 |
| 密码只存“绞碎”之后的结果（行话叫哈希，只能算过去、算不回来），算法用 Argon2id | 惯例·事实标准（OWASP 的密码存储建议）；这个算法本身是标准（RFC 9106） |
| 密码规则照美国国家标准与技术研究院的 NIST SP 800-63B-4：看长度，不强制复杂组合，不强制定期更换 | 标准（只对美国联邦系统有约束力，对你是推荐） |
| 登录状态放在只有服务器读得到的地方 | 惯例·事实标准（ASVS 第 7 章） |
| 每次读写数据，都在服务器上核对“这是不是这个人的” | 惯例·事实标准（OWASP Top 10:2025 第一项、ASVS 第 8 章） |
| 个人信息只收必要的，用户能查阅、导出一份、删除 | 行业要求（《个人信息保护法》第六条最小范围、第四十五条查阅和复制、第四十七条删除） |
| 主要流程有端到端测试：模拟真人从头点到尾 | 规范·本课程约定 |
| 维护一页“谁可能怎样捣乱”的分析 | 规范·本课程约定 |

## 技术清单（现在看不懂没关系）

- 登录：密码哈希用 pwdlib 的 Argon2id；服务器端会话加 Cookie（`HttpOnly`、`Secure`、`SameSite`）。JWT 和 OAuth 2.1 只作为对照讲。
- 权限：ownership checks，防 IDOR；默认拒绝。
- 浏览器侧：CSRF 防护、CSP 与其他安全响应头、同源部署下的 CORS。
- 清单：OWASP Top 10:2025（A01 到 A10）、ASVS 5.0.0 Level 1、OWASP Cheat Sheet Series。
- 隐私：数据清单、`/me/export`、删除账号、隐私说明；《个人信息保护法》与欧盟 GDPR 的对照只到认识的程度。
- 测试：Playwright 端到端，覆盖未登录和跨用户两类流程。
- 文档：`THREAT_MODEL.md` 第二版、`SECURITY.md`。
- 选做：OWASP Juice Shop、PortSwigger Web Security Academy。
- 规则类型的出处：OWASP Top 10:2025；ASVS 5.0.0（V7 会话、V8 授权）；OWASP Password Storage Cheat Sheet；RFC 9106；NIST SP 800-63B-4；《个人信息保护法》全文 https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm （第六、四十五、四十七条，2026-11-19 打开）。ASVS 简体中文 PDF：https://github.com/OWASP/ASVS/raw/v5.0.0/5.0/OWASP_Application_Security_Verification_Standard_5.0.0_zh-cn.pdf 。
