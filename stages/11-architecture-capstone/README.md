# 阶段 11：架构与毕业项目

> **规划用时** 150～250 小时 ｜ **前置** 阶段 9；建议先学完阶段 10 ｜ **核实日期** 2026-11-19 ｜ 回到[路线图](../../ROADMAP.md)

下面是计划，建这个阶段时会按你的真实进度和当时的工具重新定。

## 目标

自己从头设计并交付一个产品：定范围、写设计、做取舍、排计划、上线、写文档。前面十一个阶段的规范在这里全部用上。

## 作品

一个你自己设计并交付的产品。可以是汇率看板的一次大升级，比如加上提醒和多人共享；也可以是一个全新的东西。

学完时你手里有：一个别人能打开、能注册使用的网址；一份设计说明和几条决策记录（写明当初为什么这样定）；一份安全自查；每个版本的发布记录。

## 这个阶段会学到的规范（计划）

表里只标规则类型，而且是计划；约束力、谁说的、核对日期在建这个阶段时定，写在每条规范的卡片上。

| 规范 | 规则类型 |
|---|---|
| 动手前写设计说明：目标、不做什么、方案、没选的方案、风险 | 规范·组织（谷歌公开的设计文档做法） |
| 重要的决定逐条记成决策记录（模板用 MADR 4.0.0，一份公开、有版本号的模板） | 惯例·事实标准 |
| 系统图按 C4 模型（一套分四层画系统图的办法）分层次画 | 惯例·事实标准（没有版本号，算边界情况） |
| 新产品先做成一个整体，不急着拆成许多小服务 | 规范·本课程约定 |
| 设计阶段先做一页隐私影响评估 | 行业要求（《个人信息保护法》第五十五条：处理敏感个人信息、用个人信息自动做决定、委托别人处理或交给别人、公开、向境外提供等情形，要事前做个人信息保护影响评估）；不在这些情形里时类型不变，只是约束力由本课程另定 |
| 文档按用途分开写：教程、操作指南、参考、原理说明 | 惯例·事实标准（Diátaxis，一套公开的文档分类办法） |
| 毕业自查：前面所有阶段的清单逐项过一遍，每项附证据 | 规范·本课程约定 |

## 过关方式

产品在线上运行；设计说明、决策记录、安全自查、发布记录齐全；你向导师讲一遍设计并回答追问。

## 前置

阶段 9；建议先学完阶段 10。

## 规划用时

150～250 小时。

## 技术清单（现在看不懂没关系）

- 设计文档（design doc）；ADR 与 MADR 4.0.0；C4 model；Diátaxis。
- 小系统设计：monolith first、一个数据库、先纵向再横向扩展；缓存、队列、CDN 什么时候才值得加；用 Big-O 和延迟数字做粗略估算；失效模式。
- 安全与隐私：信任边界、纵深防御、最终版威胁模型、依赖清单（SBOM）。
- 可以并进来的选修：给产品加一个 AI 功能；和元框架做一次对比。见[选修分支](../../docs/roadmap/electives.md)。
- 规则类型的出处：Google 的 design docs 做法；adr.github.io/madr（4.0.0，2024-09-17）；c4model.com；《个人信息保护法》第五十五条（https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm ，2026-11-19 打开）；diataxis.fr。
