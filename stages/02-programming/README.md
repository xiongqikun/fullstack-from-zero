# 阶段 2：编程入门（Python）

> **规划用时** 150～200 小时 ｜ **前置** 学完阶段 1（阶段 1 验收 gate-1 建议先过；没过也能开始，工具会一直列出还没过的部分） ｜ **核实日期** 2026-11-19 ｜ 回到[路线图](../../ROADMAP.md)

下面是计划。课的标题、顺序和编号，建课时会按你在阶段 1 留下的真实数据重新排。

## 目标

从零学会编程：读得懂、也写得出几十到上百行的 Python（一门对初学者友好的编程语言）程序；会按固定流程排错；写出第一批测试（写给电脑执行的验收清单）。

中间穿插着学分支（一份可以放心乱改的平行草稿）、合并、合并请求（“请先看看我的改动，再决定收不收”）这些要有了代码才有意义的工程本领。

## 作品

一个在终端里使用的换算工具，名字叫 `fx`：输入金额和币种，打印换算结果。比如你敲下“100 美元换人民币”这样一行，它回你一行换算好的金额。

它是产品的计算核心，以后的数据库、接口、界面，算的都是它这套账。中间还有三个小作品练手：换算器第 0 版、猜数字游戏、换算器第 1 版。

## 过关方式

四个小作品各有完成标准；每个单元末有一次小关卡，做题时不用 AI；阶段验收的形式和每个阶段一样：全新情境里的动手任务和一个故障，做的时候不用 AI，最后把“为什么这样做”讲给导师听。

## 前置

学完阶段 1。阶段 1 验收建议先过，但它不挡阶段 2。要用到终端、编辑器、提交和推送。

## 规划用时

150～200 小时。读课文是小头，大头是你自己做练习和作品。

## 怎么学

每一课都按同一个顺序走：先猜程序会做什么，再运行，再一行一行追踪，再动手改，最后才从空白写起。这个“先读后写”的顺序有一项中学课堂上的准实验研究支持（约 500 名 11～14 岁学生，没有随机分组）；用在成年人自学上是合理的推断，不是已经证明的事。

练习不只是“写一段代码”，还有：预测题（先写下你猜的结果）、追踪表（一行一行记下每个名字的值）、排序题（把打乱的代码行排回正确的顺序）、改错题、扩写题、讲给导师听。

四条贯穿的规矩：

- 每道练习从第一课起就放在一个正规的项目文件夹里，用 uv（管理 Python 项目和它用到的第三方代码的工具）来运行。
- 每学三四课编程，插一课工程：分支、合并这些本领要在你有了代码之后学才有意义。下表里标着“工程课”。
- 每个作品开工前写一页需求和任务清单，做完写复盘。
- 每周固定两件事：一道全程不开 AI 的题；读一段八十行左右没见过的程序，讲出它在做什么。

## 逐课大纲（草案）

| 课 | 标题 | 一句话的目标 |
|---|---|---|
| 2.1 | 认识练习项目，运行第一个程序 | 学会用 `uv run` 运行程序；故意制造两种报错并读懂 |
| 2.2 | 值、类型和算式 | 数字、文字、真假是不同类型的东西；先猜一条算式的结果，再运行 |
| 2.3 | 变量与赋值 | 给一个值起名字，以后用名字来取它；“=” 在程序里读作“设为”，不是“等于” |
| 2.4 | 文字与键盘输入 | 键盘敲进来的永远是文字，要算数先得转成数字；取出一段文字的一部分 |
| 2.5 | 条件判断 | 让程序按不同的情况走不同的路 |
| 2.6 | 工程课：管道与重定向 | 把一个程序的输出交给另一个程序，或者存进文件；把文件的内容喂给程序当输入 |
| 2.7 | 作品 A：换算器第 0 版 | 先写一页需求；做一个问你金额和币种、按固定汇率换算、会检查输入的小程序；复盘；小关卡 A |
| 2.8 | while 循环 | 让程序重复做一件事，直到条件不成立；学会停下一个停不下来的程序 |
| 2.9 | for 循环 | 逐个处理一串东西；四个常用套路：累加、计数、找最大、查找 |
| 2.10 | 工程课：终端怎样找到一个命令 | 弄懂“找不到命令”这条报错；认识环境变量：每个程序出门时随身带的一张便签 |
| 2.11 | 函数（一）：定义与调用 | 把一段步骤包起来、起个名字；分清“把结果交回来”和“把结果显示出来”；从这一课起给函数写类型标注，并写下第一条“写给电脑的验收” |
| 2.12 | 函数（二）：作用域与设计 | 函数每次被调用都有一张自己的草稿纸；把一个问题拆成几个小函数 |
| 2.13 | 调试（一）：读报错，按流程排错 | 报错从最后一行读起；重现、猜测、做小实验、修改，没用就撤销 |
| 2.14 | 调试（二）：让程序一步一步走 | 用调试器让程序停在某一行，看每个名字此刻的值 |
| 2.15 | 工程课：分支 | 开一份可以放心乱改的平行草稿；分支只是一张书签，不是把文件夹复制一份 |
| 2.16 | 作品 B：猜数字游戏 | 先写需求；做出游戏；再在分支上把它重构成几个函数，玩法不变；小关卡 B |
| 2.17 | 列表 | 一排从 0 开始编号的格子：增、删、改、查、排序 |
| 2.18 | 引用与可变性 | 两个名字贴在同一个列表上会怎样；“复印一份”和“起个别名”的区别 |
| 2.19 | 工程课：合并与冲突 | 把草稿并回主线；故意制造一次冲突（两份改动改到了同一处），亲手理清 |
| 2.20 | 字典与集合 | 按名字而不是按位置来查；做计数和分组；用计时实验看“在不在里面”哪种查法快 |
| 2.21 | 嵌套的数据 | 列表里装字典，就像一张表；按其中一列排序 |
| 2.22 | 文本处理 | 切开、拼接、去掉多余的空白；把数字排成整齐的样子 |
| 2.23 | 工程课：改掉最近一次提交 | 提交说明写错了，或者漏了一个文件，怎么补；已经推送出去的历史不改，改用“再提交一次相反的改动” |
| 2.24 | 作品 C：换算器第 1 版 | 汇率放进一张表，支持多种币种和成批换算；需求、任务清单、复盘照旧；小关卡 C |
| 2.25 | 文件读写 | 从文件里读数据，把结果写进文件；认识两种常见的数据文件格式 |
| 2.26 | 数据基础（一）：文字是怎么存的 | 一个汉字在电脑里存成几个字节；乱码是怎么来的，怎么治 |
| 2.27 | 异常处理 | 出错时让程序把话说清楚、体面地停下，而不是悄悄把错吞掉 |
| 2.28 | 数据基础（二）：精确小数 | 为什么 0.1 加 0.2 不等于 0.3；算钱要换一种不出误差的小数；四舍五入的规矩 |
| 2.29 | 工程课：找回丢失的工作 | Git 记着你去过的每一个位置；把“弄丢”的提交找回来 |
| 2.30 | 模块与标准库 | 把程序拆成几个文件；用 Python 自带的工具箱；开始读官方文档 |
| 2.31 | 数据基础（三）：日期与时区 | 同一个时刻在不同地方写法不同；存储统一用一种时间；“今天”在两个地方可能不是同一天 |
| 2.32 | 第三方包 | 别人写好的现成代码怎么装进项目；“我要什么”和“实际装了什么”是两份清单 |
| 2.33 | 从网上取一份数据 | 让程序向另一台电脑要数据并读懂回信；对方不回、回错了怎么办 |
| 2.34 | 工程课：合并请求（一）走一遍流程 | 任务、分支、推送、发起合并请求、自己先看一遍、合并、删分支；远程比本地新的时候怎么对齐 |
| 2.35 | 写测试 | 用 pytest（Python 最常用的测试工具）写测试：正常情况、边界情况、错误的输入；试一次“先写测试，再写代码” |
| 2.36 | 类与对象（一） | 表格的模板和填好的表：把总是一起出现的几项数据捆成一种新的类型 |
| 2.37 | 类与对象（二） | 用几个小类型拼出大的；什么时候根本用不着它 |
| 2.38 | 工程课：合并请求（二）评审别人的改动 | 评审一份事先埋了几处问题的改动：提出具体的意见，分清轻重，要求修改 |
| 2.39 | 读代码与重构 | 读一段没见过的程序并讲出来；在测试的保护下整理代码；评审一段埋了错的 AI 代码 |
| 2.40 | 命令行程序 | 让程序接受参数、会显示帮助；用退出码告诉外界“成了还是没成” |
| 2.41～2.43 | 作品 D：换算工具 `fx` | 一页需求和任务清单；实现：读汇率文件、用精确小数、接受命令行参数、带测试；复盘，对比估计用时和实际用时 |
| 2.44 | 阶段验收 | 全新情境里的动手任务，排一个故障，做的时候不用 AI；再讲“为什么这样做” |

## 技术清单（现在看不懂没关系）

- 语言：Python 3.14（建课时核对用的版本是 3.14.9）。建课当天 Python 的最新稳定版是 3.15.2；本课程先固定在 3.14，版本号写进 `.python-version`。
- 项目工具：uv 0.13.5（`uv init`、`uv run`、`uv add`）。每道练习从第一课起就在 uv 项目里。
- 内容：值与类型、变量与赋值、字符串与 `input()`、条件、`while` 与 `for`、函数与作用域、列表、引用与可变性、字典与集合、推导式、文件与 `pathlib`、异常、模块与标准库、第三方包、类与 `@dataclass`、`argparse`。
- 数据基础：bytes 与 str、UTF-8、`encoding="utf-8"`；`float` 与 `decimal.Decimal`；`datetime`、`zoneinfo`、UTC、ISO 8601 / RFC 3339；一次 HTTP 请求和 JSON。
- 数据结构与复杂度直觉：list / dict / set / tuple 的选择，用计时实验看 O(n) 与 O(1)。
- 调试：读 traceback、print 调试、VS Code debugger、Python Tutor（https://pythontutor.com/ ）。
- 测试：先用 `assert`，再用 pytest 9.2.0。
- 练习形式：PRIMM（Predict、Run、Investigate、Modify、Make）；predict、trace、Parsons、fix、modify、make、explain、review 八类题。
- 工程课：`|`、`>`、`>>`、`<`、`2>`；`$PATH`、`export`、`which`；`git switch -c`、`git merge`、冲突标记、`git commit --amend`、`git revert`、`git reflog`、`git fetch`、`git pull`；GitHub pull request 与 GitHub Flow。
- 类型标注用内置写法：`list[float]`、`float | None`（PEP 484、PEP 604）。
- 规则类型的出处：PEP 8；ISO 4217；ISO 8601 与 RFC 3339；Python 文档 `decimal`；GitHub Docs “GitHub flow”；Google Engineering Practices（CL descriptions、review 部分）；Git 文档关于改写已发布历史的说明；岗位期望见 `standards-landscape` 调研简报第 5.2 节第 8 条。
- 关卡编号（暂定）：`gate-2`；单元小关卡的编号建课时定。
