# 阶段验收 gate-1（阶段 1 验收）：评分标准

给导师和考官用。你自己也可以先读：知道要考什么，不算作弊。

## 这一场考什么

阶段 1 的验收在第 1.16 课第 2 站，有三部分：

- **排错题**：第 1.16 课第 2 站的「自己做」。`python3 tools/course.py scenario 1.16b` 搭好一个坏掉的网站副本：一个 `.tmp` 文件被提交进了仓库。要让它留在电脑上、以后不再被 Git 管，用一个约定式提交记下，`git status` 干净，并说出是哪个提交把它带进来的（编号前 7 位）。由 `python3 tools/course.py check 1.16b` 判。
- **实操题 6 道**：第 1.11～1.16 课每课抽一道，名字每次随机，没有提示；后面几课的题也要用到第 1.1～1.10 课的本事。由工具批改。
- **讲解题**：先写进 `notes/gate-1-explain.md`，再讲给考官听：可以在平时上课的对话里对导师说“请问我 gate-1 的讲解题”，也可以新开一个不以 fullstack-from-zero 为项目文件夹的对话，用 `examiner-prompt.md`。
- **用时**：实操题看抽到哪几道，加起来约 45～55 分钟（开考前工具估的数和开考时按抽到的题重算的数会差几分钟）；讲解题约 10 分钟；排错题算在第 1.16 课第 2 站的时间里。可以分两次：先实操题，再讲解题。

## 怎样算过

- 排错题：`check 1.16b` 判它修好了。它不算在关卡里：工具说「阶段验收 gate-1 通过了」只看实操和讲解；阶段 1 学完，要 gate-1 通过，`check 1.16b` 也通过。
- 实操：第 1.11～1.16 课每一课都有一道题通过（工具判）。没通过的题，下一场换另一套题面再考，只考没通过的。
- 讲解：标「必过」的两条都够了，判「通过」，由你运行 `python3 tools/course.py exam gate-1 --explain pass`；没过是 `--explain again`，过几天换一种问法再讲。
- 三样都做到，阶段 1 才算过关。

## 讲解题

问法 A 和第 1.16 课、`notes/gate-1-explain.md` 的骨架一字不差。第一次用问法 A；上次记为 `again` 的，用问法 B。讲解时不提示，评的时候不教。

### 讲解题 1：秘密在提交之前挡住

- 问法 A：为什么密码、令牌这类文件要在提交之前就用 .gitignore 挡住，而不是提交以后再删掉？
- 问法 B：假如你把一个令牌文件提交并推送到了 GitHub，第二天把它删掉、再提交一次。为什么这还不算解决了？应该怎么做？
- **够了的回答里有**：(1) 提交会被历史一直留着：后来删掉，只是新的提交里没有了，旧提交里还在，谁拿到这个仓库都能翻出来；(2) 推送以后它就离开了你的电脑，到了别人（或者自动扫描的程序）能拿到的地方，收不回来；所以只能在提交之前挡住（`.gitignore`，推送前用第 1.12 课的 `git grep` 查一遍）。问法 B 还要说出：先作废那个令牌、换一个新的。
- **这样还不够**：“删掉就看不见了”；“因为 .gitignore 是规定”，说不出原因；只说“为了安全”；以为私有仓库就不用管（私有仓库没有人替你拦，以后也可能公开或被别人复制）。

### 讲解题 2：真正的备份

- 问法 A：为什么学习仓库要推送到 GitHub、并且试着克隆回来，而不是只靠 iCloud 同步来备份？
- 问法 B：有人说“我的文件夹开了 iCloud 同步，等于有备份了”。为什么对一个 Git 仓库来说这不够？你在第 1.12 课是怎么确认备份真的能用的？
- **够了的回答里有**：(1) 同步是“两边一模一样”：一边删了、坏了，另一边跟着删、跟着坏，它不是一份独立的备份；Git 官方 FAQ 还专门说不要用云同步来同步仓库，仓库可能被弄坏，要用推送和拉取；(2) 推送到 GitHub 是在别处有一份带完整历史的独立副本；(3) 没试过恢复的备份不算数，所以克隆回练习场、和原来的比一比（`diff -r -q`），确认能用。至少 (1)、(3) 两点。
- **这样还不够**：“GitHub 更安全”“大家都用 GitHub”，说不出同步和备份差在哪；“因为课程要求”；只说推送，没说为什么要克隆回来试一次。
