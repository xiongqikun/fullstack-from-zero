## 讲解题

第一次用问法 A；上次记为 `again` 的，用问法 B。一道一道问，不提示，评的时候不教。

### 讲解题 1：提交前先看改了什么

- 问法 A：为什么提交之前要先用 `git diff` 和 `git diff --staged` 看清改了什么，而不是 `git add` 完直接提交？
- 问法 B：你刚 `git add` 了一个文件，`git diff` 却什么都不显示。改动丢了吗？为什么提交前还要再看一眼 `git diff --staged`？
- **够了的回答里有**：(1) 提交记下的是暂存区里的东西，不是你以为你改了的东西：手滑的一行、调试用的字、甚至密钥，都会跟着进历史，进了历史就很难拿掉（推上网以后别人也能看到）；(2) `git diff` 比的是工作区和暂存区，`git add` 以后它就空了，要看即将提交的内容用 `git diff --staged`（问法 B：改动没丢，在暂存区里）。两点都要有。
- **这样还不够**：“反正就是看看有没有问题”“为了规范”，说不出看的是哪两样东西的差别、为什么要在提交之前而不是之后看；以为 `git diff` 什么都不显示就是改动丢了。

### 讲解题 2：已经提交过的东西

- 问法 A：为什么一个已经被提交的文件，写进 `.gitignore` 以后 Git 还在跟踪它？如果那是一个装着密钥的文件，为什么第一步是去作废密钥？
- 问法 B：你发现 `.env`（里面有一个令牌）已经在上一个提交里了。为什么只把 `.env` 写进 `.gitignore` 不够？正确的顺序是什么？
- **够了的回答里有**：(1) `.gitignore` 只管还没被跟踪的文件，已经提交过的要用 `git rm --cached` 让 Git 放手（文件留在电脑上）；(2) 就算放手了，旧提交里还存着那份内容，有这份历史的人都能翻出来，所以先作废那把密钥、换一把新的，然后才清理仓库。顺序：作废 → 写进 `.gitignore`、`git rm --cached`（这两步先后都行，第 1.9 课先写名单）→ 提交。
- **这样还不够**：“把文件删了就好”“写进 `.gitignore` 就安全了”；顺序反了（先清理仓库、最后才想到作废，或者根本不作废）。

## 排错题

导师把下面一段贴给学习者（第一次用 A，补考用 B），请他不运行、只读，答报错三问，说原因和改法。输出在 2026-11-19 的模拟环境里实际运行过（Git 2.54.0）。

- **A**：在一个仓库里，文件夹里的文件是 `index.html` 和 `style.css`。他运行了 `git add index.htm`，看到：

  ```text
  fatal: pathspec 'index.htm' did not match any files
  ```

  够了：谁在报错是 Git（`fatal:` 开头）；关键词 pathspec … did not match any files（这个路径对不上任何文件）；我敲的文件名少了一个 `l`。改法：先 `ls` 或 `git status` 看真实的名字，再 `git add index.html`（用 Tab 补全更好）。也说得出另外两种常见原因（新文件还没保存、不在仓库那个文件夹里）更好，不要求。

- **B**：在一台打开了提交签名、却没装 gpg 的电脑上，他运行了 `git commit -m "test"`，看到：

  ```text
  error: cannot run gpg: No such file or directory
  error: gpg failed to sign the data:
  (no gpg output)
  fatal: failed to write commit object
  ```

  够了：谁在报错是 Git，它去叫 gpg 来签名；关键词 cannot run gpg、failed to sign（找不到 gpg、没签上名），所以提交没写成；原因是全局设置里 `commit.gpgsign` 是 `true`，可电脑上没有 gpg。改法（第 1.6 课）：先备份 `~/.gitconfig`，再自己敲 `git config set --global commit.gpgsign false`；或者按第 1.11 课改用 SSH 签名。

- **两种都不够**：加 `sudo`；重装 Git；说“提交成功了，只是有警告”；只说“打错了”，说不出错在哪。
