# Markdown 速查

> 只收第 1.5 课和第 1.13 课用到的写法。写法按 CommonMark 0.31.2（2024-01-28 发布，2026-11-19 打开核对，目前最新）。在 VS Code 里看到的样子没法在建课时实测，标着〔对照文档，界面可能不同〕。
> 所有符号都是**半角**的：先切到英文输入法再打。中文输入法打出的 `＃`、`【】`、`（）`，Markdown 都不认，也不报错，只当普通文字显示。

## 写法

| 想要的效果 | 怎么写 | 要点 | 哪一课 |
|---|---|---|---|
| 一级标题 / 二级标题 | `# 总标题` / `## 小节` | `#` 后面一定要有一个空格；一个文件只放一个一级标题（本课程约定） | 1.5 |
| 列表 | `- 第一项` | `-` 后面有一个空格；每项一行；列表前后各空一行 | 1.5 |
| 加粗 | `**要紧的话**` | 两边各两个星号 | 1.5 |
| 行内代码 | `` `cd` `` | 一句话里的命令或文件名，两边各一个反引号 | 1.5 |
| 代码块 | 上下各一行三个反引号 | 中间几行原样显示；开头那行写上是哪种代码，终端命令写 `zsh` | 1.5 |
| 链接 | `[显示的文字](https://网址)` | 方括号紧挨圆括号，中间不空格 | 1.5 |
| 指向仓库里另一个文件的链接 | `[LICENSE](LICENSE)` | 相对链接：从这份文件所在的文件夹算起 | 1.13 |

代码块的样子：

````markdown
```zsh
cd ~/Developer/playground
```
````

## 在哪里写、怎么看

| 操作 | 做什么 | 哪一课 |
|---|---|---|
| 文件名以 `.md` 结尾 | `.md` 是 Markdown 文件的扩展名 | 1.5 |
| `cat <文件>.md` | 在终端里看原文：看到的是符号，不是排好版的样子 | 1.5 |
| ⇧⌘V〔对照文档，界面可能不同〕 | 在 VS Code 里打开预览：只是看，不改文件 | 1.5 |
| ⌘K，然后按 V〔对照文档，界面可能不同〕 | 预览出现在右边，一边写一边看 | 1.5 |

和你看到的不一样？把屏幕上的内容发给导师，说“课文对不上”。

## README 回答五个问题（DOC-02）

放在项目根目录，名字是 `README.md`（DOC-01）。依次回答；第 1 个问题写在一级标题下面的一两句里，其余每个问题一个小节：

1. 这是什么？
2. 怎么用，或者怎么看到效果？
3. 文件夹里有什么？
4. 现在的状态和下一步打算？
5. 作者是谁、用什么许可证？（许可证在第 1.13 课补上）

骨架在 `templates/readme-template.md`。没话可说的小节宁可不写，也不留空壳。

## 旧教程提醒

> **旧教程提醒**：以前不少教程里 `#标题`（`#` 后面不空格）也算标题，最早的 Markdown 说明（John Gruber 的 Markdown Syntax 页面）也没规定这个空格；现在 CommonMark 规定必须有，GitHub 显示 Markdown 文件也改用了 CommonMark（自 2017-03-14 起，见 GitHub 官方博客《A formal spec for GitHub Flavored Markdown》）。照老教程不写空格，今天的预览里只会得到一行普通文字。（第 1.5 课）

> **旧教程提醒**：以前很多 README 开头手写一份目录；现在 GitHub 会按标题自动生成目录（自 2021-04-13 起，见 GitHub 的更新公告（GitHub Changelog）「Table of Contents support in Markdown files」），短的 README 不用手写目录。（第 1.5 课）
