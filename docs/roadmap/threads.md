## 规范线：每个阶段的作品都按已学的规范做

### 每条规范带的四个标记

每条规范带四个标记：约束力、规则类型、谁说的、核对日期（外加多久复核一次）。

**约束力**说它在这里对你有多强制：必须、推荐、参考，括号里写适用范围（本课程 / 本机 / 所在团队 / 所有项目）。

**规则类型**说它是谁定的，共七种。这门课出发点里的四个词，标准、行业要求、惯例、规范，正好对上：

| 规则类型 | 意思 |
|---|---|
| 标准 | 标准组织正式发布、带编号的文件，比如互联网的 RFC、万维网联盟的推荐标准、国标、Python 的 PEP |
| 行业要求 | 别人可以拿它追究你：法律法规、合同、审计、平台的强制政策 |
| 惯例·事实标准 | 公开、有版本号、很多独立项目和工具都照着做的社区规范，比如语义化版本、约定式提交 |
| 惯例·平台与工具 | 某个工具或平台本身的工作方式或期待，包括它在自己的官方文档里教你怎样用它 |
| 规范·组织 | 一家组织以自己的名义写的做法指南，写给自己的工程师（比如谷歌的代码评审指南），或者写给自己的读者（比如 MDN 的教程）；别人自愿借用 |
| 规范·团队约定 | 一个团队或一个仓库自己定的 |
| 规范·本课程约定 | 本课程为了学习自己定的，是团队约定的一种 |

雇主对从业者的普遍期望单独标成“岗位期望”，不和法律义务混在一起。真正可以自己决定的事会明说是“个人偏好”，它不是规则。

日常说话里，“规范”也是所有这些的总称；在规则卡片上，它只指“规范·组织”和“规范·团队约定”这一类。

约束力和规则类型是两回事。同一份标准，没人引用时对你只是推荐或参考；被法律或合同引用之后就成了必须。它还是标准：规则类型分好就不再变，处境变了，变的只是约束力。第 0.3 课教你一个按顺序问的判断法，问到第一个“是”就停；七步的原文在[规范地图](../../STANDARDS.md)第 2 节。

第 0.3 课的 META-02 问三件事：谁说的、多强制、哪年的版本。它们在卡片上写成谁说的、约束力、核对日期；再加上规则类型，就是四个标记。

全部规范的总图在 [`STANDARDS.md`](../../STANDARDS.md)。学过的每一条的完整卡片在 `handbook/`（规范手册，随课程一起长）。你用自己的话写的版本在 `notes/my-rules.md`，那个文件是你的，课程不改。

### 每个阶段新学哪些方面的规范

| 阶段 | 新学哪些方面的规范 | 用在哪 |
|---|---|---|
| 0 | 怎么读一条规范（谁说的、多强制、哪年的版本）；代码放哪、怎么命名；任务要有完成标准 | 你的学习计划 |
| 1 | 终端里的安全习惯；项目说明书；怎样存档、存档说明怎么写；什么不该进仓库；账号安全；公开之前查什么；AI 的改动先看再收 | 你的网页和学习仓库 |
| 2 | 代码的写法和命名；钱和时间在程序里的规范写法；分支与合并请求；评审的礼节 | 换算小工具 |
| 3 | 项目的结构；依赖（你的程序用到的、别人写的代码）怎么锁定；自动排版和检查；测试；版本号和更新日志；配置和密钥；流水线 | 小工具升级成正规项目 |
| 4 | 表怎么设计和命名；查询怎么写才安全；表结构怎么改 | 历史汇率数据库 |
| 5 | 接口的通行约定：怎么命名、怎么表示成功和失败、怎么分批给数据 | 数据窗口 |
| 6 | 网页内容的标准写法；无障碍；浏览器的安全规则 | 手写网页 |
| 7 | 前端项目的同一套四件事：排版、检查、类型、测试 | 看板新界面 |
| 8 | 公开的安全清单；密码和登录的做法；法律对个人信息的要求 | 登录和个人设置 |
| 9 | 上线、回退、备份、监控的做法；故障复盘 | 上线的看板 |
| 10 | 团队怎么分工、评审、发版、开复盘会 | 一轮团队迭代 |
| 11 | 设计说明和决策记录怎么写 | 毕业作品 |

每条规范的名字和规则类型，在各阶段的页面上，比如[阶段 1](../../stages/01-foundations/README.md)。

规范只增不减：阶段 N 的作品要守住前面所有阶段学过的规范。讲的顺序是先让你在练习场里尝到不守规范的麻烦，再给规范。每课最多两条新的。这三条都是规范·本课程约定。

## 管理线：从管自己的学习，到模拟一个团队

| 阶段 | 发生什么 |
|---|---|
| 0 | 给学习定任务和完成标准；定每周计划和固定的复盘时间 |
| 1 | 每次学习写一句话日志；阶段末拿估计用时和实际用时对比，做阶段复盘 |
| 2 | 每个小作品开工前写一页需求（给谁用、做到什么算完成、这次不做什么）和任务清单；做完复盘 |
| 3 | 任务上看板；“完成的定义”落成一条检查命令；动手前写一页设计说明和一条决策记录；第一次发布照发布清单走 |
| 4 | 给数据写一份“户口本”：每一项是什么、从哪来、留多久 |
| 5 | 先写接口的说明，再写实现；升级一个第三方依赖有固定的流程 |
| 6～7 | 把一个界面需求拆成能单独交付的小步；继续记录估算和实际差多少 |
| 8 | 写一页“谁可能怎样捣乱”的分析；列出收集了哪些个人信息 |
| 9 | 上线清单、回退演练、成本清单；第一次正式的故障复盘 |
| 10 | 团队模拟：任务清单里有说不清的需求、缺陷报告和依赖漏洞；AI 当队友提交改动，由你评审，有时要退回；处理一次故障；写一份进度报告 |
| 11 | 自己定范围、里程碑和风险清单，把毕业项目从头管到尾 |

## 交付线：早上线，常上线

| 阶段 | 发生什么 |
|---|---|
| 1 | 手写的静态网页（内容固定、不需要后端的网页）放到网上 |
| 2 | 没有新的上线。学会分支和合并请求，为阶段 3 的自动检查铺路 |
| 3 | 每次推送自动检查；第一次打版本标签并发布 |
| 4 | 数据库结构的每次变化进仓库；第一次用一个现成的装箱工具（Docker，把程序和它要的一切打成一个包的工具）在你自己的电脑上开起一个数据库，插上就用，先不管里面怎么装的；备份并试着恢复 |
| 5 | 第一个后端上线。计划让它从这天起一直在线，后面的阶段都在照看它 |
| 6 | 网页改由流水线自动发布；亲眼看网址里的名字（域名）怎样被翻译成服务器的数字地址，看网站的证书（网站用来证明“我是我”的电子证件）长什么样 |
| 7 | 前端打包成一份成品，由你的后端一并送出 |
| 8 | 分开“试用环境”和“正式环境”；密钥交给托管平台专门存密钥的地方，不写在文件里 |
| 9 | 深入：把程序连同运行环境装箱、流水线自动上线、不停机改数据库、监控和提醒、备份恢复演练、回退演练、自己的网址 |
| 10 | 照看一个运行中的服务：定期更新依赖、对线上数据做一次结构变更、处理一次故障 |
| 11 | 毕业作品从第一天起就带着流水线 |

## 排错线：每个阶段都有排错练习

| 阶段 | 发生什么 |
|---|---|
| 0 | 第一次故意出错；学“报错三问” |
| 1 | 排错实验室：八种坏掉的情况，先不找 AI，自己试 |
| 2 | 调试专题：从最后一行读报错；按“重现、猜测、验证”排错；让程序一步一步走 |
| 3 | 读懂流水线为什么变红；用测试把问题的范围越缩越小 |
| 4 | 查询为什么慢：看数据库打算怎么查；读懂数据库的报错 |
| 5 | 追踪一次网络请求：发出去的是什么，回来的是什么，卡在哪一层 |
| 6 | 用浏览器自带的检查工具看页面结构、看报错、看网络请求 |
| 7 | 界面“不更新”“更新了两次”这类问题；读懂 TypeScript 那层检查的报错 |
| 8 | 一个问题横跨界面、服务器和数据库时怎么定位 |
| 9 | 线上的问题：看运行记录和监控；分清“连不上、超时、证书不对、服务器报错” |
| 10 | 一次事故演练和复盘 |
| 11 | 给自己的系统设计一次故障演练 |

## 安全线：从“密钥永不进仓库”开始

| 阶段 | 发生什么 |
|---|---|
| 1 | 密钥、密码、令牌（token，一种临时的通行证）永不进仓库；账号开双重验证；公开之前检查有没有密钥和隐私；不照抄看不懂的命令 |
| 2 | 外面进来的输入都不可信，先检查再用；需要随机的密码时用专门的工具生成；别人给的数据只当数据读，不当成程序去运行（Python 里有几个会这么做的功能，要避开）；新建项目时别把邮箱带进公开仓库 |
| 3 | 第三方代码的安全：锁定版本、查已知漏洞、新版本先等几天再用；配置和密钥分开；运行记录里不留密钥和个人信息；流水线只给够用的权限 |
| 4 | 查询里填的永远只是“内容”，不是“指令”：先攻击自己的练习库，再修好；数据库账号只给够用的权限；建表时只收用得上的个人信息 |
| 5 | 进门安检：所有进来的数据在接口处检查；出错时不向外泄露内部细节；你的程序按用户给的网址去别处取东西时，防止有人借它去碰不该碰的内部地址；写第一版“谁可能怎样捣乱”的分析 |
| 6 | 浏览器的安全规则：不同网站之间默认互相读不到；Cookie（浏览器替网站记住你的小纸条）有三个安全设置，分别管网页里的程序读不读得到、只走加密连接、别的网站能不能顺带把它发出去；别人贴进来的内容显示之前先处理成纯文字，免得里面藏的代码被浏览器执行；全程加密连接 |
| 7 | 界面代码里没有秘密；登录凭证不放进浏览器里任何网页程序都读得到的那块存储；安装第三方包的安全习惯 |
| 8 | 合拢：登录和密码的正确做法；用测试证明“甲看不到乙的数据”；对照公开的安全清单逐项自查；个人信息能导出、能删除 |
| 9 | 服务器和流水线的安全：登录服务器只用密钥文件、不用密码；程序不用管理员身份运行；密钥交给平台专门存密钥的地方；证书自动续期；备份可恢复；密钥泄露之后的处置流程 |
| 10 | 团队层面：安全检查进入评审流程；漏洞怎样私下报告；人员进出时权限怎么开、怎么关 |
| 11 | 设计阶段就考虑安全和隐私：哪里是信任的边界、一页隐私影响评估、毕业自查清单 |

法律底线（行业要求：《网络安全法》禁止非法侵入他人网络；2025 年修正后条号有变）：攻击练习只对你自己的东西做，或者在明确提供练习的平台上做。

## 与 AI 协作的阶梯：导师、评审者、搭档、受托方

这条阶梯只管课程里的练习。在别的项目里，AI 照常替你干活。

| 阶段 | AI 的角色 | AI 可以做 | 必须你自己做 | 过关时 |
|---|---|---|---|---|
| 0～2 | 导师 | 讲概念、给提示、出题、在你做完之后讲评 | 练习里的每条命令、每行代码都由你敲；报错先自己读 | 关卡任务不用 AI |
| 3 | 评审者 | 再加一样：评审你写好的改动，指出问题，但不替你改 | 先自己评一遍，再请它评；它指出的问题由你来改；你也评审它写的东西 | 同上；另加评审一份 AI 写的改动 |
| 4～8 | 搭档 | 再加一样：替你写“你已经亲手做过一遍”的那类重复劳动 | 每样新东西第一遍手写；它写的每一行你都读过、讲得出 | 同上；新学的内容不用 AI 做出来 |
| 9～11 | 受托方 | 再加一样：照你写的任务说明和测试，独立完成一块工作 | 写任务说明和完成标准；逐行验收；合并、上线、删除这类决定 | 同上；另加验收一份委托出去的工作，讲清你查了什么 |

一句话的规矩：**先手写，再对照，后委托**（规范·本课程约定）。往上走一级不等于丢掉下面的：到了阶段 9，遇到新概念，AI 仍然先当导师。

为什么这样排：

- Anthropic（做 Claude 的公司）在 2026 年 1 月公布过一项随机对照试验（把人随机分成两组、只改一个条件来比较）。52 名工程师（多数是初级）学一个没用过的 Python 工具库。用 AI 帮忙的一组，事后测验平均 50%；手写的一组 67%；差距最大的是调试题。用 AI 的一组快了约两分钟，但统计上不显著，也就是差距小到可能只是碰巧。
- 同一项研究还按用法分了小组：只向 AI 问概念的 7 个人得分在 65% 左右，把任务整个交出去的 4 个人约 39%。这两组人很少，只能当线索看。
- 2025 年发表在《美国国家科学院院刊》上的一项实验里，近千名高中生做数学题。不加限制的 AI 让练习成绩提高 48%，撤掉 AI 之后的考试成绩反而比从没用过的人低 17%；加了“只给提示、不给答案”这类限制的辅导版，让练习成绩提高 127%，负面影响大部分消除。
- 验收是真实工作里的日常：Stack Overflow（一个程序员问答网站）2026 年的开发者调查里，问到怎样对待 AI 的产出，只有 9.6% 的人选“原样拿来用”，76.5% 的人选先在自己电脑上运行。

这两项实验的对象分别是初级工程师和高中生，时间都不长。针对成年人长期自学的直接研究，建课调研没有找到。

## 英文阶梯：一级一级把拐杖撤掉

这是默认安排，讲解给多细，按你在第 0.1 课入学问卷里对英文的回答来调。

| 阶段 | 发生什么 |
|---|---|
| 0～1 | 你会遇到的英文报错和输出，课文原样给出，后面跟一句“读懂这句”；每条命令给一次全称当记忆钩子，比如 `pwd` 是 print working directory，打印当前所在目录 |
| 2 | 报错后面的中文讲解逐步撤掉；每课认几个英文术语；学到“模块与标准库”那一课起，读 Python 官方教程，先读中文版，再对照英文版 |

| 5 起 | 提交说明和合并请求的描述改用英文。到时由你决定要不要改 |
| 全程 | 程序里起的名字一律用英文（规范·本课程约定），课程给一份常用的命名词表；有官方中文版的资料先给中文版 |

想单独补英文，可以看 freeCodeCamp 的“English for Developers”两门免费课，网址在本页的技术清单里。

## 原理线：计算机与网络基础，用到哪讲到哪

| 阶段 | 发生什么 |
|---|---|
| 0 | 一台电脑和一个软件各由哪几块组成 |
| 1 | 文件和路径；Git 存的是“快照加书签” |
| 2 | 程序怎样一行一行执行；内存和硬盘的区别；文字、数字、时间在电脑里怎么存；哪种存放数据的办法查得快；终端是怎么找到一个命令的 |
| 3 | 程序之间怎么传话；依赖、锁文件、项目专用的运行环境各是什么 |
| 4 | 为什么要数据库；表和表的关系；“要么全成、要么全不成”；查找为什么能很快 |
| 5 | 一次网络请求的旅程：网址、域名、连接、加密、请求和应答；接口是一份约定；“在等”和“在算”的区别 |
| 6 | 浏览器怎样把文件变成页面；页面为什么会卡住 |
| 7 | 界面由小部件拼成一棵树；数据还没回来时界面怎么办 |
| 8 | 登录背后三种常被混为一谈的处理：单向“绞碎”（只能算过去、算不回来，用来存密码）、换一种写法（谁都能换回来，不保密）、加密（有钥匙的人才能解开） |
| 9 | 服务器上的同一套概念：正在运行的程序、域名记录、证书；“装箱”到底是什么 |
| 10 | 存档历史是一张图；接口和表结构的变化，是人和人之间约定的变化 |
| 11 | 小系统的设计：先做成一个整体；什么时候才需要更多部件；粗略的估算 |
