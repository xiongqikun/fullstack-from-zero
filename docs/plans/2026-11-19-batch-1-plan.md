# Batch 1 Implementation Plan: stages 0-1 and the learning system

> **For agentic workers:** this plan is executed through orchestrated workflows (the user opted into multi-agent orchestration). Each task is built by one agent and verified by a different one. Read the sections your task brief names. Where the plan leaves a choice open, make a reasonable one and report it. Do not improvise against a constraint in section 1.

**Goal:** Build the first deliverable of a zero-to-professional full-stack learning workspace: a roadmap and a norms map, a tutor contract, a learning toolchain (checks, hints, practice scenarios, spaced review, cold exams, environment doctor, freshness check) and 20 hands-on lessons in plain Chinese (stage 0: 4 lessons, stage 1: 16 lessons), every command verified against the reference environment of G7.

**Architecture:** One folder per lesson containing the lesson text, a small Python module with that lesson's checks/hints/review items/scenarios, and the rule cards it introduces. One standard-library CLI (`tools/course.py`) discovers and loads those modules. Lesson folders are self-contained so they can be written in parallel; shared documents (handbook, glossary, roadmap, norms map) are assembled afterwards by single writers. All learner state lives in files inside the workspace, so nothing depends on chat history.

**Tech stack:** GitHub-Flavored Markdown; Python standard library only, compatible with Python 3.9 through 3.14; zsh on macOS 27; Git 2.54. No third-party packages. No network access at run time.

**Spec:** `docs/design/2026-11-19-fullstack-learning-workspace-design.md`. Product decisions: the spec wins over this plan. Facts (versions, flags, behaviour): what was verified on the machine or in a primary source today wins over both, and the discrepancy is reported.

## 1. Global constraints

**G1. Purpose.** The course is for an adult who starts from zero and wants to build professional full-stack engineering skills. It must tell the learner which norms, standards, industry requirements and conventions (规范、标准、行业要求、惯例) apply, and keep up with current practice (与时俱进). Two consequences bind every file: (a) whenever a practice is taught, the learner is told what kind of rule it is, who says so, how binding it is, and when that was last verified; (b) nothing outdated is taught, and where old tutorials differ the difference is pointed out.

**G2. Audience and voice.** A Chinese-speaking adult with no programming background. Plain Chinese (大白话), second person 「你」, short sentences, one idea per paragraph. A technical term at first use is written `中文（English）` followed by a one-clause everyday explanation; after that the Chinese term is used. No "很简单", "显然", "只需要". No cheerleading, no exclamation marks, no emoji in lesson prose (the CLI may use ✅ ❌ ⚠️). Chinese full-width punctuation in prose, half-width inside code, one space between Chinese and Latin letters or digits. Never talk down; give a reason and, where the learner can choose, the choice.

**G3. Norm labelling (the four words of G1).** Revised 2026-11-19 after the `standards-landscape` research (its section 3 is the reference; read it). Every rule the course states carries two independent labels, a source and a date. Never merge the two axes.

- **约束力** (how strongly it applies here): **必须** / **推荐** / **参考**, with its scope in brackets (本课程 / 本机 / 所在团队 / 所有项目). These line up with MUST / SHOULD / MAY of RFC 2119 and with 强制 / 推荐 / 参考 of the Alibaba manual.
- **规则类型** (who wrote it), exactly one of these seven labels, which map onto the four words of G1:
  - **标准**: issued by a standards body and carrying a designation or number (ISO/IEC, IETF RFC, W3C, WHATWG, Ecma, Unicode, GB, Python PEPs).
  - **行业要求**: something a third party can hold you to: law, regulation, contract, audit, or a platform's mandatory policy. What employers expect of a professional is labelled **岗位期望** instead, so a hiring expectation is never confused with a legal duty.
  - **惯例·事实标准**: a public, versioned community specification that many independent projects and tools follow (Semantic Versioning, Conventional Commits, Keep a Changelog, EditorConfig, CommonMark, the Scrum Guide).
  - **惯例·平台与工具**: simply how a tool or platform works or what it expects (a README in the repository root, `.gitignore`, where code lives on a Mac).
  - **规范·组织**: written by one organisation for its own engineers and adopted voluntarily by others (Google's style guides and review practices, the Alibaba manual).
  - **规范·团队约定**: decided by this team or this repository. Rules that exist only because this course chose them are written **规范·本课程约定**.
  - **个人偏好**: not a rule. Never the type of a rule card; lessons say it out loud when something is genuinely free choice.
- **谁说的**: name, version or date, URL. **核对日期**: the day it was checked (today is 2026-11-19), with a **复核周期**.
- Say once, where the labels are introduced, that in everyday Chinese 规范 is also the umbrella word for all of these; on a rule card the narrow sense applies.
- The decision procedure taught in lesson 0.3 (ask in order, stop at the first yes): can a regulator, court, customer, auditor or platform penalise me? → 行业要求. Does it have an issuing standards body and a number? → 标准. Is it a public, versioned specification that many tools follow? → 惯例·事实标准. Is it simply how one tool or platform works? → 惯例·平台与工具. Did one organisation write it for its own engineers? → 规范·组织. Did this team or this course decide it? → 规范·团队约定. Otherwise → 个人偏好.

**G4. Freshness (与时俱进).** No version number, flag, default or "best practice" from memory. Verify on the machine or in the primary source and tag it. Every lesson module carries `verified` metadata (date, tool versions). Where older tutorials would mislead, add a box `> **旧教程提醒**：以前……；现在……（自 <版本或年份> 起）`. The tool baseline lives in `tools/courselib/baseline.json`.

**G5. Unit budget.** A lesson is 2 or 3 stations (站). A station is 20-25 minutes, ends at a save point (存档点), introduces **one** new concept and at most **five** new commands, and has exactly one independent exercise with one check. At most **two** new rule cards per lesson. Anything else is deferred or dropped. A lesson's 「跟我做」 part must be completable without the tutor.

**G5a. Honest minutes (revision of G5 after the first blind tests, 2026-11-19).** Blind testers timed most stations at 30-45 minutes although every station was labelled 25. A false "25" tells a slow beginner that they are slow, so honesty outranks the 20-25 target:

- `minutes` in META and every time the lesson text states are the **calculated** time for a slow-typing beginner who does the required parts and skips 「想多了解」 boxes. They are never adjusted to fit a target. The 20-25 minutes of G5 stay the target; `validate` accepts 15-40, warns above 30 and rejects anything above 40. A station that calculates above 40 must lose material (move it into a 「想多了解（可跳过）」 box, into a later lesson that already owns the topic, or drop it); a station between 26 and 40 is first trimmed where a cut is clean and then labelled with the calculated number.
- **The calculation** (builders and testers use the same one, so that they argue about facts, not feelings): prose outside code blocks and outside 「想多了解」 boxes at 180 Chinese characters per minute; each line of output the learner has to read at 10 seconds (at most 2 minutes per block); each command the learner types at 40 seconds, or 70 seconds when it is longer than 40 characters or contains quotes or a pipe; Chinese text the learner has to compose (notes, README text, answers) at 15 characters per minute; each GUI action sequence (open an app, a menu path, a browser round trip) at 1 minute, with first-time flows (sign-up, install, a settings page) estimated one by one; each check run at 1 minute plus 45 seconds per question it asks; each exchange with the tutor at 2 minutes; plus 3 minutes per station for one failed attempt. Add up and round **up** to the next multiple of 5.
- One new concept per station stays a hard rule. A second concept is reduced to a one-clause gloss, moved into a 「想多了解（可跳过）」 box, or moved to the lesson that owns it.
- Gate exams are budgeted separately from stations: the lesson names the gate as its own sitting with its own save point and states its time (the sum of the tasks' `minutes` plus 10 minutes for the explain-back part: two explain-back questions, at gate-0, gate-a and gate-b one debugging question, the verdict and the command that records it). A station's `minutes` never include a gate.
- The hours in `ROADMAP.md` and the stage READMEs are derived from these numbers (station minutes plus gate minutes plus 15% for reviews), not the other way round.
- Rulings of 2026-11-20: "Chinese characters" means Han characters only (punctuation, digits, Latin letters and inline code are not counted). A lesson's closing section is calculated the same way, without the 3 minutes for a failed attempt, and rounded up to the next multiple of 5; the fixed 5 or 10 minutes are withdrawn. Record: docs/authoring/build-kit/COMMON.md, section "Rulings of 2026-11-20".

**G6. Verification classes.** Every step in a lesson is one of: 已实测 (executed in a simulation with the learner's configuration: no mark needed), 仅对照官方文档 (GUI or online steps checked against official documentation: mark it `〔对照文档，界面可能不同〕`), 无法验证 (mark it `〔建课时无法验证〕`). Any marked step is followed once per lesson by the line: 「和你看到的不一样？把屏幕上的内容发给导师，说"课文对不上"。」

**G7. The reference environment** (the reference Mac (plan G7), checked read-only in an interactive terminal on 2026-11-19; write lessons against this, not against the build sandbox):

- macOS 27.2.1 on Apple silicon. Do not assume the system UI language (it may be English or Chinese): quote UI labels in English with a Chinese gloss.
- Shell zsh 5.9, default prompt `用户名@电脑名 当前文件夹 %`. `LANG=C.UTF-8`. `EDITOR` and `PAGER` unset, so Git's editor is **vi** and its pager is **less**.
- The terminal the learner uses in stages 0-1 is the Terminal panel of the Claude desktop app (`TERM_PROGRAM=claude-desktop`), a normal login zsh. Terminal.app, the VS Code integrated terminal and similar terminals are the same shell in other windows.
- `python3` is 3.14.9 (uv-managed, first on PATH); `/usr/bin/python3` is 3.9.6. `python` also exists on the reference Mac (a uv-managed link to 3.14.9), but many Macs have no `python`: lessons always write `python3`. There is no `pip`; `pip3` is the Xcode Python 3.9 one and is not used.
- Git 2.54.0 (Apple Git-157). Default branch is `main` only because Xcode's bundled system gitconfig says so; `init.defaultBranch` is not set globally. Global settings differ from Mac to Mac; the course prepares for a common bad case, and the simulation home reproduces it: user.name, user.email, `commit.gpgsign=true`, `gpg.format=openpgp`, `gpg.program=gpg`, user.signingkey, `tag.forceSignAnnotated=false`, `core.excludesfile=~/.gitignore_global`, and the two keys `gpg.ssh.program` and `gpg.ssh.allowedSignersFile` present with **empty** values. **With no gpg installed, every `git commit` then fails until this is handled.**
- A global ignore file may already ignore common files; the simulation's `~/.gitignore_global` ignores `.DS_Store`, `._*`, `.Spotlight-V100`, `.Trashes`, `.idea/`, `*.swp`, `*.swo`, `*.log`. Demonstrations of ignoring must use other files.
- Tool versions the lessons were checked with: uv 0.13.5, ruff 0.17.2, Node 26.12.0 with npm 11.20.0 (nvm), Homebrew 7.0.10 (`/opt/homebrew`), VS Code 1.145.2 with the `code` command, sqlite3 3.54. **Not installed:** gh, gpg, pnpm, psql, tree.
- Desktop and Documents are often iCloud-synced; the course assumes they may be. `~/Developer` often does not exist yet.

**G8. Simulation parity.** Agents verify lessons in a throwaway home directory that mimics G7, never in the real home:

```bash
export SIM="$TMPDIR/sim-$(date +%s)-$RANDOM"; mkdir -p "$SIM/home/Developer"
cp -R <workspace> "$SIM/home/Developer/fullstack-from-zero"
export HOME="$SIM/home"            # inside the simulation shell only
git config --global user.name "Learner"; git config --global user.email "learner@example.com"
git config --global commit.gpgsign true; git config --global gpg.format openpgp
git config --global gpg.program gpg;   git config --global user.signingkey FAKEKEY0000
git config --global core.excludesfile "$HOME/.gitignore_global"   # create it with the eight patterns from G7
```

`tools/dev/make_sim_home.py` automates this. Every workaround an agent needs that the learner would not have (an environment variable, a flag, a substitute path) must be reported, and must never leak into lesson text.

**G9. Safety rules for builders and testers.** Write only inside the workspace and your scratch directory under `$TMPDIR`. Never touch the real `~/.gitconfig`, `~/.zshrc`, `~/Developer`, the learner's other projects, or anything else under the real home. No global installs, no upgrades, no accounts, no pushes, no credentials. The Bash sandbox blocks listening on ports, `open`, and network unless hosts are passed in `allowed_domains`. Before `uv`: `export UV_CACHE_DIR="$TMPDIR/uv-cache"`. Use `/Library/Developer/CommandLineTools/usr/bin/python3` to test Python 3.9 compatibility (the `/usr/bin/python3` shim can fail in the sandbox). Commit nothing in the workspace: the learner makes every commit.

**G10. Privacy.** Never write the learner's real name, user name, e-mail address or computer name into any file. Use `~`, `你的用户名`, `你的电脑名`, `you@example.com`. Sample prompts read `你的用户名@你的电脑名 fullstack-from-zero %`.

**G10a. Publishable (added 2026-11-20).** The course is written so that it can be published as it stands; `python3 tools/dev/export_public.py <new folder>` makes the public copy. (1) Course files hold no facts about one particular learner or their computer: not their projects, their words, their plans, their time zone, the software they installed or their settings. Where a lesson must react to the reader's situation it says so conditionally (「如果你的电脑……」) and lets `doctor`, a check or the tutor find out. Tailoring to one learner (from `learner/profile.md`, `learner/log.jsonl`, the tutor's notes) happens at run time and is never written into `stages/`, `docs/` or any other builder-owned file. The evidence taken from one learner's files (numbers, answers, the date and content of their decisions) and notes on how their computer differs from a lesson are kept in `learner/` (`learner/arrangements.md`, `learner/machine-differences.md`, `learner/stage-<N>-evidence.md`), which is never exported and is backed up with the learner's private repository from lesson 1.12; public files state only conclusions that hold for any reader. `docs/research/local-only/` is for builders' private material only. (2) Examples and cases come from public sources a reader can open, cited with the address and the date they were checked (G4), or are invented and plainly marked as invented. A private project, private data or the build machine is never the evidence for a claim. (3) Measurements of the learner's own projects, if any are ever made, go only into `docs/research/local-only/`, which is never exported. (4) Terms that must never reach the public copy (the names of private projects, for example) are listed in `docs/research/local-only/public-denylist.txt`, one per line; `python3 tools/dev/export_public.py --check` exits 0 before a stage is delivered.

**G11. Ownership.** Builder-owned (the course may rewrite them in later batches): `README.md`, `ROADMAP.md`, `STANDARDS.md`, `GLOSSARY.md`, `CHANGELOG.md`, `CLAUDE.md`, `stages/`, `handbook/`, `gates/`, `starter/`, `cheatsheets/`, `templates/`, `tools/`, `docs/`. Learner-owned (the course never overwrites them): `notes/`, `journal/`, `learner/profile.md`. Tool-owned state: `learner/state.json`, `learner/log.jsonl`, `learner/last-result.json`, `PROGRESS.md` (generated). The tutor writes only to tool-owned state, `learner/misconceptions.md`, journal entries dictated by the learner, and errata fixes that are logged in `CHANGELOG.md`.

**G11a. Starter material (added 2026-11-19).** Two rules follow from the fact that lessons let the learner touch `starter/`. (1) A file under `starter/` that a lesson tells the learner to edit in place (today only `starter/hello-fx/convert.py`, lesson 0.1c) is never rewritten by a later batch; new practice material goes into new folders. (2) Scenarios, state-ladder builds and exams never depend on the learner's copy of `starter/`: the tool keeps a manifest of the original starter files and builds from the originals, and `doctor` reports starter files that differ from the manifest (apart from the files of rule 1).

**G12. Naming.** Folders and documents: lowercase English words joined by hyphens (kebab-case). Python files: snake_case. Conventional upper-case names are kept (`README.md`, `LICENSE`, `CHANGELOG.md`, `CLAUDE.md`, `ROADMAP.md`). Dates: `YYYY-MM-DD`. Lesson ids: `<stage>.<n>` (`0.1` ... `1.16`); station ids: lesson id plus a letter (`1.6a`). State this rule with its exceptions wherever naming is taught.

**G13. Inputs.** Research briefs (read the ones your task names; they are verified notes, not lesson text): `docs/research/<topic>.md` for the topics `uv-packaging`, `quality-tooling`, `git-norms`, `github-collab-ci`, `review-testing-practice`, `project-mgmt-norms`, `security-config-logging`, `research-code-engineering`, `pedagogy-prior-art`, `ai-pairing-norms`, `fullstack-curricula`, `frontend-stack-2026`, `backend-data-stack-2026`, `delivery-ops-2026`, `beginner-programming-pedagogy`, `foundations-macos`, `skill-model`, `web-security-2026`, `cs-fundamentals`, `standards-landscape`, `currency-mechanisms`, plus, where one exists, a local-only audit of the learner's existing project under `docs/research/local-only/` (kept out of the repository by `.gitignore`). These are sanitised copies (user name, e-mail address and computer name replaced by placeholders) of the briefs the builders worked from on 2026-11-19; a build prompt may also name a scratch copy of the same briefs. The five reviews of design v1 were simulated reviews and are not published with the course.

**G14. English ladder.** Stages 0-1: every English output or error the learner is likely to see is shown verbatim and followed by `> 读懂这句：` with a plain Chinese reading; each command gets its expansion once as a memory hook (`pwd` = print working directory = 打印当前所在目录).

**G15. Three practice places.** `~/Developer/fullstack-from-zero` (the course and the learner's notes; becomes a private repository in 1.12), `~/Developer/playground/` (disposable practice states created by the tool; safe to break), `~/Developer/my-site/` (the learner's own one-page website; becomes a public repository and goes online in 1.13). Exercises never touch anything else on the computer. The tutor never performs an exercise in the learner's real repositories.

## 3. Interfaces

### I1. Lesson text: `lesson.md`

```markdown
# 1.6 Git：第一次提交

> **用时** 3 站，约 65 分钟 ｜ **前置** 1.5 ｜ **核实** 2026-11-19 · git 2.54 · macOS 27.2
> **学完你能** ……（两到三件看得见的事）
> **本课行规** GIT-01、GIT-02（见文末）

## 先想一想
（一个靠生活经验就能答的问题，2 分钟；在第 1 站的概念之后回头对答案）

## 第 1 站：……（约 20 分钟）
### 概念
（一个新概念。类比之后必须有一句"这个类比在哪里不成立"。）
### 跟我做
（带小标题的分步。每条命令：代码块；`你应该看到`原样输出；英文输出后接 `> 读懂这句：`；每两三条命令前加一句"先猜它会输出什么"；每站一个故意出错的步骤，并用"报错三问"读它。）
### 补全
（半成品题：给出步骤骨架，留空让学习者填。）
### 自己做
（只给目标，换一个和"跟我做"表面不同的情境。提示：`python3 tools/course.py hint 1.6a`；检查：`python3 tools/course.py check 1.6a`）
> **存档点 1.6a**：到这里可以安全停下。下次对导师说"从 1.6b 继续"。

## 第 2 站：…… （同上）

## 本课行规
（最多两张规则卡的摘要：约束力、规则类型、谁说的、核对日期；完整卡片在 rules.md）

## 收尾（5 分钟）
1. 全课检查：`python3 tools/course.py check 1.6`
2. 用自己的话把本课行规各写一句到 `notes/my-rules.md`
3. 一句话日志：`python3 tools/course.py journal`
```

Rules for the text: the Git lessons reuse one unchanged four-area diagram (工作区 / 暂存区 / 本地历史 / 远程), drawn in ASCII; every worked Git step is paired with a `git status` or `git log --oneline` view and the question 「先说出执行后图会怎么变」. The "报错三问" are: 谁在报错（哪个程序）？关键词是什么？我刚才敲了什么？ No folded answers in the text: hints come from the tool. Optional reading goes under a final `## 想多了解` with at most three links, each marked 中文 or English.

### I2. Rule cards: `rules.md` (one fragment per lesson)

```markdown
### GIT-03 提交前先看改了什么

- **规则类型**：惯例·平台与工具
- **规则**：（可以照着做的一句话）
- **谁说的**：（名称 + 版本或日期 + 网址）
- **核对日期**：2026-11-19；**复核周期**：12 个月（或写触发条件）
- **谁来管**：（法律 / 客户或审计 / 平台 / 工具 / 评审人 / 没有人）；**不遵守的后果**：（一句话）
- **为什么**：（两三句，讲后果，不讲大道理）
- **正例**：（可照抄）
- **反例**：
- **怎么检查**：（自检命令或复习题编号；无法自动检查就写"人工检查：……"）
- **例外**：（什么时候可以不遵守；没有就写"无"）
- **旧教程提醒**：（老资料里的过时说法 → 现在的做法；没有就写"无"）

```

All thirteen fields are mandatory and `validate` enforces them: 规则类型 must be one of the seven labels of G3 other than 个人偏好, and 核对日期 must be a date. This format follows section 7 of the `standards-landscape` brief, which has five complete sample cards. Rule ids are fixed in section 4. A card is introduced only after the lesson has let the learner feel the problem the rule prevents. In section 4 the bracket after each rule id gives only the family of the label: the card itself must carry one of the seven full labels, chosen honestly from the source.

### I3. Lesson module: `lesson.py`

Plain Python, standard library only, importable on 3.9. It defines data and small functions; the framework (task T1) fixes the exact helper API and documents it in `docs/authoring/tool-api.md`. Required names:

- `META`: dict with `id`, `slug`, `title`, `stage`, `prerequisites` (list of lesson ids), `stations` (list of dicts: `id`, `title`, `minutes`, `new_concept`, `new_commands`), `rules` (rule ids), `verified` (`date`, `tools` dict), `unverified_steps` (list of strings).
- `TERMS`: list of dicts `term`, `en`, `plain`, `first` (station id).
- `checks`: mapping from station id to a check function. A check receives a context object and returns results through it. Three kinds exist: **artifact** (inspect files and repositories read-only), **ask** (ask the learner a question whose answer can only be obtained by doing the task; answers may be computed from a seeded scenario), **quiz** (auto-graded multiple choice for concept stations).
- `HINTS`: mapping from station id to a list of exactly four strings: 方向 → 位置 → 相似例子 → 答案与解释.
- `REVIEW`: list of dicts `id`, `type` (`recall` | `predict` | `which` | `fault` | `do`), `tier` (`fluent` | `lookup` | `aware`), `q`, `a` or `options` + `answer`, and for `do` items a scenario id and a check. Only `fluent` items are scheduled.
- `SCENARIOS`: mapping from scenario id to a builder function that creates a practice state under the playground. Every lesson defines `start`: the state a learner has just before this lesson (used by testers and by learners who need to rebuild).
- `EXAM`: list of cold tasks for the gate named in section 4: each has two parallel forms, a scenario builder that randomises names from a seed, the task text, and a grading function.

### I4. The CLI: `python3 tools/course.py <command>`

| Command | Behaviour |
|---|---|
| (none) or `status [--write]` | Where the learner is, the next step, stations left to the next landing point, hours logged, review items due, days since the last session (more than 10: suggest the return routine), and a notice when 70% of the stage is done. `--write` regenerates `PROGRESS.md`. |
| `check <station or lesson>` | Optionally asks for a 1-5 confidence rating first (Enter skips). Runs the check. Prints exactly one of three outcomes: **通过** / **还没达标**（看了哪里、看到了什么、还缺什么，不给答案）/ **检查器出问题**（「这不是你的错，把这段发给导师」）. Never prints a traceback. Logs the attempt, the outcome and the highest hint level used. |
| `hint <station>` | Prints the next hint level (1-4) and logs it. After level 4 the station is marked 带扶手完成 and a cold redo is scheduled 3-7 days later. |
| `scenario <id> [--reset]` | Builds a practice state under the playground and prints where it is and what to do. Refuses to overwrite a non-empty folder without `--reset`; deletes only folders that contain the marker file `.playground`. |
| `review` | At most 8 due items or 10 minutes. Leitner boxes at 2 days / 1 week / 3 weeks / 2 months / 6 months. `recall` items are self-graded after revealing the answer; `which`, `fault`, `predict` are auto-graded; `do` items build a scenario and are graded by their check. Skippable. |
| `exam <gate> [--grade]` | Cold practical: builds one task for each lesson the gate covers (I7), with randomised names, no hints. `--grade` verifies and records the result per task. |
| `journal [--done T --stuck T --next T]` | Appends an entry with three one-line fields (做了什么 / 卡在哪 / 下次从哪开始) to `journal/YYYY-MM-DD.md`; prompts for them when flags are absent. Optional fourth and fifth fields: 哪里看不懂 / 哪里太慢. |
| `doctor [--net]` | Read-only environment report in three groups: 没问题 / 需要处理 / 仅提示. Covers OS, shell, python3, Git version and the settings that matter (identity present or not, never printed; signing sanity; editor; default branch), where the workspace lives (inside an iCloud-synced folder or not), whether `~/Developer` exists, the `code` command, and with `--net` whether github.com is reachable. |
| `fresh` | Compares installed tool versions with `tools/courselib/baseline.json` and lists the lessons whose `verified.tools` are affected. Read-only, no network. |
| `validate` | For builders: loads every lesson module, checks the interface in I3, the budgets in G5, that every rule id in section 4 has a card, and that every station has a check and four hints. |

Exit codes: 0 passed / ok, 1 not yet, 2 checker problem, 64 usage error. All output is Chinese. Colours only when stdout is a terminal and `NO_COLOR` is unset. Environment overrides for tests: `COURSE_PLAYGROUND` (default `~/Developer/playground`), `COURSE_NOW` (ISO date-time used as "now"), `COURSE_NONINTERACTIVE=1` (never prompt; read answers from `--answer`). The tool reads Git state only through machine-readable commands (`git status --porcelain=v1`, `git rev-parse`, `git for-each-ref`, `git log --format=...`) with a timeout, never modifies a repository it checks, and never needs the network except `doctor --net`.

### I5. State files

`learner/state.json` (schema version 1): `stations` (per station: first pass time, attempts, highest hint level, confidence, status `passed` | `assisted` | `open`), `review` (per item: box, due date, history), `exams` (per gate and task: form, result, date), `sessions` (date, minutes), `decisions` (free-form keys such as `workspace_location`, `commit_signing`). `learner/log.jsonl`: append-only, one JSON event per line with a timestamp. `learner/last-result.json`: the last check result, for the tutor to read. Writes are atomic (write a temporary file, then rename). A missing or corrupt state file is reported as 检查器出问题 with a recovery instruction, never as a crash.

### I7. Gates

`gate-0` (inside 0.4), `gate-a` (after 1.5), `gate-b` (after 1.10), `gate-1` (inside 1.16). Each gate has: 8-12 observable criteria of which 3-4 are must-pass (`gates/<id>/rubric.md`), cold practical tasks in two parallel forms (from the lessons' `EXAM` lists; every lesson the gate covers has at least one), two explain-back questions and one debugging task, and `examiner-prompt.md`: an examiner-only prompt for a fresh conversation that sees the rubric and the evidence and must quote evidence per criterion. One sitting holds one task for each lesson the gate covers (gate-0 four, gate-a and gate-b five, gate-1 six: the lessons 1.11-1.16, whose tasks also use the skills of the earlier lessons; no gate borrows tasks of another). A lesson counts once one of its tasks is passed; a fail produces a short practice list, and the next sitting holds only the lessons not passed yet, each with the failed task in its other form. The explain-back verdict is recorded with `python3 tools/course.py exam <gate> --explain pass` (or `again`). A gate is passed when every lesson it covers has a passed task and the explain-back is recorded as pass. A gate never blocks the next lesson; `check`, `status` and `journal` keep naming it until it is passed (tool-api.md sections 6.8 and 15.5).

## 6. Review focus

1. **The learner's shell is not the build sandbox.** A command that works for an agent can fail for the learner (signing, vi as editor, the less pager, PATH). Every Git lesson is tested in a simulation home built by `make_sim_home.py`.
2. **The checker must never cry wolf.** A false "还没达标" or a traceback destroys trust in the only objective signal. Every check is tested with correct work, three wrong attempts and a broken environment.
3. **Steps nobody could click through.** VS Code, GitHub's website and the Claude app cannot be operated by the builders. Those steps are marked (G6), kept few, and written from official documentation checked today.
4. **Too much per station.** The commonest way these lessons fail a beginner. The budgets in G5 are enforced by `validate` and counted again by the independent tester.
5. **Rules stated without a source or a date.** That is the one thing the course promises above all (G1). `validate` rejects a rule card that lacks any field of I2, and the independent tester opens every cited source.
