# 0007 学习工具只用 Python 标准库，并且在 Python 3.9 到 3.14 上都能运行

> **状态**：已采纳（accepted）｜ **日期**：2026-11-19 ｜ **谁定的**：Claude 在建课计划里定的，属于工具内部的技术细节，错了由它负责改 ｜ **征求过意见**：资深工程师评审、失败预演评审

## 背景和要回答的问题

学习工具（`tools/course.py`，负责自动检查、提示、复习、环境体检）是从第一课起就要在你电脑上运行的程序，用 Python 写成。建课时核对用的那台 Mac 上有两个 Python（这里指运行 Python 程序的那个程序）：平时敲 `python3` 得到的是 3.14.9（uv 装的），系统自带的那个是 3.9.6；只装了命令行开发者工具的 Mac 上，`python3` 就是 3.9。终端（terminal，用打字指挥电脑的窗口）换一种启动方式，就可能拿到 3.9。要回答的是：工具可以依赖什么，要支持哪些版本？

## 考虑过的方案

* 甲：用第三方包（third-party package，别人写好、要另外下载安装的功能），比如拿专业的测试工具 pytest 来做检查。
* 乙：只用标准库（standard library，装好 Python 就自带的功能），但只照顾最新的 3.14。
* 丙：只用标准库，并且从 3.9 到 3.14 都能运行。

## 决定

选丙。甲意味着第一课之前先要联网安装东西，而且 pytest 从 9.0 版起已经不支持 Python 3.9。乙的问题是：一旦拿到的是 3.9，为 3.14 写的工具会报出一条你读不懂的错误。自动检查是你手里唯一客观的信号，它自己不能先坏。

### 后果

* 好处：阶段 0～1 不用为工具安装任何东西，不联网也能用。不管是哪一个 `python3` 来运行，结果都一样。
* 代价：工具的代码不能用 3.10 以后才有的新写法，很多功能要自己动手写，不能借现成的包。所以工具的源代码（source code，程序的原文）不是“现在的项目该怎么写”的示范；正规项目怎么使用和管理第三方包，放在后面的阶段学。
* 代价：每次改工具，都要在 3.14 和 3.9 上各跑一遍测试。
* 上限为什么是 3.14：Python 3.15 已经在 2026-10-09 发布，工具还没有在它上面测过。你的 `python3` 升级之后，运行 `python3 tools/course.py fresh`，它会列出哪些课需要重新核实。
* 什么时候重新考虑：系统自带的 Python 不再是 3.9 时，把下限往上提；下一批建课时，把上限往上提并重测。

## 技术清单（现在看不懂没关系）

* 建课时核对用的 Mac（建课计划 G7）：`python3` 是 3.14.9（uv 管理，PATH 上最先找到），`/usr/bin/python3` 是 3.9.6，没有 `pip`。出处：建课计划 G7，2026-11-19。
* 版本状态：3.9 已于 2025-10-31 停止维护（end-of-life）；3.14 于 2025-10-07 首次发布；3.15 于 2026-10-09 首次发布。出处：https://devguide.python.org/versions/ ，2026-11-19 核实。支持 3.9，是因为它是苹果开发者工具自带的版本，不是因为它还值得用来写新项目。
* pytest 9.0.0（2025-11-05）的更新记录：“Support for Python 3.9 is dropped following its end of life.” 出处：https://docs.pytest.org/en/stable/changelog.html ，2026-11-19 核实。
* 评审：资深工程师评审第 22 条（检查器要兼容 3.9，否则报错没法读）；失败预演评审第 8 条（检查器要先说明自己运行在哪个版本上）。调研里的原型检查器只用标准库，在 3.9～3.14 上运行过（调研简报 pedagogy-prior-art 第 2.4 节）。
* 测试：`tools/tests/` 用标准库的 `unittest`，在 3.14 和 3.9 上各跑一遍（建课计划 T1）。
