# 0008 远程平台用 GitHub，用不了时有后备做法

> **状态**：已采纳（accepted）｜ **日期**：2026-11-19 ｜ **谁定的**：Claude 提出；账号由你自己注册，你也可以不注册 ｜ **征求过意见**：教学设计、资深工程师、零基础视角三份评审

## 背景和要回答的问题

代码搬出 iCloud（苹果的网盘）之后，第二份拷贝要靠远程仓库（remote，见记录 0004）：放在别处的另一份仓库。仓库（repository）是被 Git 管着的文件夹，Git 是给文件夹拍“带说明的快照”的工具。后面的阶段还要有一个地方做三件事：展示作品，练习“先看改动、再决定收不收”的协作流程，让检查自动运行。第 1 版把 GitHub 那一课标成了选修。评审（建课前给第 1 版设计挑错的意见，共五份）指出，后面的阶段离不开它，备份也指望它，不能是选修。要回答的是：用哪个平台？用不了怎么办？

## 考虑过的方案

* 甲：GitHub（存放快照备份、也能展示作品的网站）。
* 乙：别的同类网站，例如 GitLab、Gitee、GitCode。
* 丙：不用任何网站，只在本机或另一块磁盘上留第二份。

## 决定

默认选甲。课程文件夹 `fullstack-from-zero` 推送（push，把快照传上去）到一个私有仓库（private，只有你能看），在第 1.12 课做；你的网页 `my-site` 放进一个公开仓库（public，谁都能看），用 GitHub Pages（GitHub 提供的放网页的功能）上线，在第 1.13 课做。账号在第 1.11 课由你自己注册和登录，免费，注册时要一个邮箱。课程不索要、也不保存你的密码。

后备做法分三层。第一，推送之前：第 0.4 课先做一个临时备份。第二，GitHub 打不开，或者你决定不注册：Git 本身不依赖 GitHub，远程仓库可以放在乙里的任何一家，也可以是另一块磁盘上的一个仓库，或者一个打包文件（bundle，Git 能把整个仓库连同历史打成一个文件）。过关条件不变，仍然是“在别处有第二份，并且试过能恢复”。第三，GitHub Pages 用不了：第 1.13 课要给出替代的上线办法。

### 后果

* 好处：备份、展示、协作练习、自动检查都在同一个地方。后面阶段计划用的自动检查工具 GitHub Actions 就是这个平台的功能。
* 代价：免费账号下，GitHub Pages 只对公开仓库开放。所以学习记录和网页分成两个仓库：一个私有，一个公开。
* 代价：公开仓库里，每张快照上记的邮箱谁都看得到。第 1.11 课教你换成 GitHub 提供的隐私地址。
* 代价：走后备路线时，Git 的用法不变，但 GitHub Pages、自动检查的写法、GitHub 自己的命令行工具 `gh` 这些是 GitHub 特有的，要另找对应的东西。
* 什么时候重新考虑：`python3 tools/course.py doctor --net` 多次报告连不上 github.com 时，把后备路线升为主线，并新写一篇记录。

## 技术清单（现在看不懂没关系）

* GitHub Free 的范围：公开和私有仓库数量不限，私有仓库功能受限；“GitHub Pages in public repositories”；GitHub Actions 每月含 12 美元的计算额度。出处：https://docs.github.com/en/get-started/learning-about-github/githubs-plans ，2026-11-19 核实。
* 双重验证：GitHub 自 2023 年 3 月起要求在 GitHub.com 上贡献代码的用户开启，被选中后有 45 天的期限。出处：GitHub Docs “About mandatory two-factor authentication”，2026-11-19 核实。对应规则卡 ACC-01。
* 后备做法今天在 Git 2.54.0 上实测过：`git bundle create` 打包后用 `git clone` 取出，内容和原件一致；`git init --bare` 建的仓库当远程，推送后再克隆，内容和原件一致。
* 评审：教学设计评审第 20 条（GitHub 设为默认路线，本地仓库作离线后备）；资深工程师评审第 5 条（没有账号时用 `git bundle`）和第 21 条（网络受限时加第二个远程）；零基础视角评审第 9、24 条。平台对照见调研简报 github-collab-ci 第 9 节。
