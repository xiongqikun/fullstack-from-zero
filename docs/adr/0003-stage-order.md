# 0003 阶段顺序：先数据和后端，再现代前端；网页在阶段 1 先上线一次

> **状态**：已采纳（accepted）｜ **日期**：2026-11-19 ｜ **谁定的**：Claude 定顺序并解释理由；主题和节奏由你定 ｜ **征求过意见**：资深工程师、教学设计、失败预演三份评审

## 背景和要回答的问题

先认四个词。前端（front end）是用户看得见的界面；后端（back end）是在服务器（server，一直开着、替别人干活的电脑）上干活、不露面的程序；数据库（database）是专门存数据的程序；上线（deploy，也叫部署）是把东西放到服务器上，让别人能通过网址打开。

第 1 版设计的顺序是：Python → 规范 → 网页基础 → 后端 → 现代前端。评审（建课前给第 1 版设计挑错的意见，共五份）指出两个问题。一是 JavaScript（让网页动起来的编程语言）在网页基础阶段学完后，要闲置 100～140 小时才再用到。二是你第一次有东西放在网上，要等到累计 250～360 小时之后。要回答的是：阶段怎么排？

## 考虑过的方案

* 甲：维持第 1 版的顺序。
* 乙：把“数据与 SQL”（SQL 是向数据库提问用的语言）和“后端”提到“Web 基础”（手写网页的基本功）前面；“现代前端”（用成套的工具做界面）内部先学 TypeScript（在 JavaScript 上加了一层检查的语言），再学 React（做网页界面的工具）；另外在阶段 1 就手写一个静态网页（static page，内容固定、不需要后端的网页）并上线。
* 丙：先前端，后后端。这是多数教做网站的免费课程的顺序。它和“先学 JavaScript”配套，而记录 0002 已经选了先学 Python。

## 决定

选乙，因为它把背景里的两个问题都解决了：JavaScript 学完紧接着用；第一批课学完，就有东西放在网上。顺序是：阶段 2 Python → 3 专业开发规范 → 4 数据与 SQL → 5 后端与接口设计（接口，英文缩写 API，是程序之间约定好的问答方式）→ 6 Web 基础 → 7 现代前端。两个固定点。一是先 TypeScript，后 React：在 2025 年一项一万多人回答的调查里，多数受访者写网页代码时主要用 TypeScript；先学它，免得用不带检查的写法学一遍 React，之后再改一遍。二是第 1.13 课把你手写的网页放到网上。

### 后果

* 好处：JavaScript 在阶段 6 学，阶段 7 接着用，中间不闲置。你写的第一个带数据的网页，取的是你自己在阶段 5 做的“数据窗口”里的数。
* 好处：第一批课（约 25～30 小时）学完，你就有一个网址可以给别人看。之后上线这件事一层层加深：阶段 3 加自动检查，阶段 5 上线后端，阶段 9 深入。
* 代价：你自己写的、能点能输入的界面来得晚。把路线图里阶段 0 到 5 的规划用时加起来，进入阶段 6 之前大约是 365～500 小时。
* 代价：阶段 1 的网页是先用起来（改一个现成的起步网页），网页的原理到阶段 6 才系统地学。
* 什么时候重新考虑：每个阶段建课之前，都按你当时的进度和当时的工具重新核对这一段的顺序。

## 技术清单（现在看不懂没关系）

* JavaScript 闲置和乙的顺序：资深工程师评审第 15 条。先例：CS50 第 7 周讲 SQL、第 9 周讲 Flask；boot.dev 先讲 SQL 再讲 HTTP 服务器（调研简报 fullstack-curricula 第 4 节；backend-data-stack-2026 第 1 节也建议先手写 SQL）。
* 先 TypeScript 再 React：State of JS 2025 调查里，受访者所写代码中 TypeScript 占比的中位数是 88%，10,934 人里有 4,367 人全部用 TypeScript（https://2025.stateofjs.com/en-US/usage/ ）；TypeScript 在 2025 年 8 月成为 GitHub 上每月贡献者最多的语言（GitHub Octoverse 2025）。两条都在 2026-11-19 核实。教学顺序见调研简报 frontend-stack-2026 第 7 节。
* 早上线的先例：The Odin Project 的第一个作业就用 GitHub Pages 发布；MDN “Your first website” 的最后一篇是 “Publishing your website”。2026-11-19 核实。
